# 全体画面プロトタイプ（Issue #48・#62・#76・#80・#95）

`prototype/index.html` をブラウザで直接開く。ビルド、通信、外部ライブラリは不要。架空の社員・データを使い、変更はブラウザのメモリにだけ保持する。再読み込みで初期状態に戻る。

初期画面は S-01 ホーム（「ようこそ、{表示名}さん」と短い案内だけを表示する）。上部に検索・通知・自分のメニュー、左側（サイドバー）にチャンネル（会社・自部署・他部署）・DM・スレッド・案件・整理スペース・共通（社員一覧）・管理をこの順に配置した（「管理」は最下部の項目で、ロールに応じた項目だけが出る。一般メンバーには出ない。C-116）（会社のワークスペースは1つで、切替はない。C-93）。チャンネルなどの大きな項目は開閉できる（案。下の「サイドバーの開閉」）。画面幅768px未満をスマートフォン表示（下部ナビ5項目とメニュードロワー）、768px以上をパソコン表示とする2段階で、タブレット専用の配置はない。右下の「画面確認」で社員・画面番号・表示状態（読み込み中／データあり／データなし／エラー）を切り替えられ、下書きの確認用ボタンとサイドバーの開閉の確認用ボタンもある。#76 で、確認用ボタンを3つ足した（「無効化の見本の部署（企画部）を追加」「企画部のオーナーを引き継いで異動したことにする（見本）」「ABC の今年の連番を9999にする（見本）」）。オーナー交代・オーナーの異動・9999件の案件はこの試作で再現できないため、状態だけを作る確認用の道具で、業務の操作・手順を決めたものではない。この確認道具は業務ナビではない。#80 では確認用ボタンを増やしていない（「企画部」の見本には、申請中の案件作成の申請 R-201 を1件含める）。#95 でも確認用ボタンは増やしていない（アーカイブ・物理削除・添付・書式・リアクションは、通常の画面の操作で確かめる。コンソールから呼ぶ実行する関数は下の確認手順に挙げた）。権限外の画面は番号から開いても内容を表示しない。

ファイル構成: `index.html`（入口）、`extras.js`（下書き・サイドバーの開閉の保存・入力の長さ・離脱の確認・スレッド一覧・取引先の管理）、`screens.js`（共通レイアウトと各画面。#95 段階1：件名・説明の検査 `cleanCaseText`、添付の検査 `cleanAttachments`、投稿を確定する関数 `postMessage`、送信前の添付の一覧）、`admin.js`（再認証の票 `issueReauthTicket`・`consumeReauthTicket`（#95 段階2）、部署の作成 S-08・チャンネル招待 S-12・退職処理の申請 S-13・アカウント管理 S-22・部署の一覧 S-24、拠点ラベルの管理と設定、部署の無効化と担当部署の付け替え、確認用の見本の部署）、`organize.js`（個人整理スペース S-33、各画面からの登録、添付ファイルの表示）、`announce.js`（お知らせ専用チャンネルの依頼・緊急削除の申請・直接削除・自分の投稿の編集・削除、S-37、通知。#76）、`app.js`（案件の状態と権限、納期の変更、案件番号の連番と前方一致、保存時の自動整形の関数 `normalizeInput`・`compareKey`、類似件名の判定 `similarCases`。#95 段階1：案件の再編集 `editCase`・`cleanCaseEdit`、納期の変更の権限 `canChangeDue`、添付の公開可否の変更 `changeAttachmentScope`。段階2：アーカイブ・復元・物理削除 `archiveCase`・`restoreCase`・`purgeCase`・`archiveChannel` ほか、チャンネルの名前・説明の変更 `editChannel`、返信 `postThreadReply`、案件の更新を確定する14個の関数 `addCaseMember`・`removeCaseMember`・`saveTodo`・`deleteTodo`・`setTodoDone`・`closeCaseNow`・`reopenCaseNow`・`submitPublicationRequest`・`withdrawPublicationRequest`・`judgePublication`・`revokePublication`・`submitReopenRequest`・`withdrawReopenRequest`・`judgeReopen`。旧 `archiveCase`（終了）は `closeCase` に改名）、`style.css`・`shell.css`・`organize.css`。#95 段階3：`screens.js` に、書式 `renderMarkdown`（トークンに分けてから組み立てる自前の最小実装。外部ライブラリなし）、リアクション `toggleReaction`、絵文字・スタンプの選択画面（`REACTION_EMOJI`・`STAMPS`・`openPicker` など）を足した。読み込み順は `extras.js` → `screens.js` → `admin.js` → `organize.js` → `announce.js` → `app.js`。

## 権限と案件について反映した合意

単一会社。一般社員と部署オーナーの新規案件申請先は所属部署のみ（有効な社員は必ず部署に所属する。所属なしは退職者で、ログインできない）。全体管理者は部署を選択できる（#99：決定 C-132(1) により、誰でも全部署から複数を選べる形に置き換えた。元の記述は残す）。申請者は承認時に自動参加し、他部署の有効社員も候補にできる。承認者は候補追加のみ可能で、自動参加しない。部署オーナーの自己承認は不可、全体管理者は自己承認可能。却下理由は必須で履歴を残し、再申請は別申請とする。

進行中の内容は参加者のみ閲覧・更新可能。非参加者には件名・状態・部署・進捗の概要だけを表示する。参加者は有効社員を追加・削除できるが最後の1人は外せない。終了時は参加者限定の読み取り専用。参加者の公開申請を部署オーナーまたは全体管理者が承認すると有効な全社員が過去の会話・TODO・資料を閲覧できる。公開審査中のみ権限者に読み取り専用の一時閲覧を許し、その閲覧を監査へ記録する。

公開済みアーカイブは、部署オーナーまたは全体管理者が理由・再認証見本・監査記録を伴う公開取消を行える。案件は終了のまま参加者限定になり、非参加者の管理者も内容を見られなくなる。すでにダウンロードされた情報は回収できない。参加者が残る終了案件は参加者が直接再開でき、参加者ゼロの終了案件は全有効社員が再開申請できる。再開後は過去も含め参加者限定。審査中の公開申請は再開で自動取消する。

## #99 追加（決定 C-133〜C-135）全体管理者と担当部署のオーナーの強制参加の確認手順

決定（C-133 を C-134 で拡張）：有効なすべての全体管理者（退職・無効でない `admin`。兼任のオーナーも全体管理者として数える）は、すべての案件（アーカイブ・終了を含む）に自動で参加する。加えて、案件の担当部署のオーナー（すべての担当部署）も自動で参加する。どちらも参加者から外せない（外れるのは、全体管理者でなくなる・退職する、またはその部署が担当部署から外れる・オーナーが交代したとき。外れた後は一般の参加者として残り、外せる）。交代・新任の全体管理者、担当部署の追加・オーナーの交代があれば、新しい人が自動で参加する。参加者として、メッセージ・TODO・添付（公開範囲に従う）も見られる（全体管理者は「概要だけ」ではなくなった。アーカイブした案件の中身も、全体管理者だけは強制参加の参加者として読み取り専用で見られる。他の人は従来どおり見られない：Q-70・C-135）。決定 C-135：アーカイブ（非表示）した案件の中身（メッセージ・TODO・資料）は、強制参加の参加者である全体管理者だけが、S-38 の「中身を見る」または S-40 の「⋯」から、読み取り専用で見られる（操作は復元だけ）。オーナー・一般の参加者は従来どおり見られない。アーカイブした案件は、担当部署の一括付け替えの対象にもならない（変更・参加者の追加・履歴を残さない。部署の無効化の妨げにもならない）。リアクション・返信も使えない。参加・外れたことの通知は出さず、監査ログだけに残す（Q-116。案件番号と対象者を残す）。

試作の持ち方：「外せない参加者」の項目は保存しない。有効な全体管理者と、案件の `departments` が担当する部署の有効なオーナー（`forcedMembers`・`isForcedMember`。旧 `caseOwners`）から導く。参加者の追加は `syncForcedMembers`（重複させない。通知は出さない）で行い、承認（案件の生成）・再編集（`editCase`）・付け替え（`reassignDepartmentCases`）・再開（`reopenCaseNow`・`judgeReopen`）、起動時と部署の作成に伴うオーナーの交代（`syncAllForcedMembers`）から呼ぶ。外せないことは `removeCaseMember` で拒否し、S-18 の「外す」ボタンは出さず「全体管理者」または「担当部署のオーナー」と表示する（S-17 の参加者の一覧にも表示）。全体管理者の任命・解除・退職の専用画面は洗い出しにない（唯一の全体管理者は無効化できない）ため、試作ではコンソールで `role` を変えて `syncAllForcedMembers()` を呼んで確かめる。デモ案件には起動時に全体管理者 `testuser_005` が加わる。「参加者ゼロ」（Q-117）は、強制参加者を除いて一般の参加者がいないことに直した（見本 `倉庫移転の事前調査`（`C-101`）は、`testuser_005` だけが参加）。

以前の手順のうち、`testuser_005`（全体管理者）や営業部オーナー `testuser_002`・設計部オーナー `testuser_004` を「参加していない」前提にしたものは、C-133・C-134 により自動参加するため、コンソールで `getCase(id).members` から外した状態で確かめる。

## ヘッダーのステータス切り替え（決定 C-136。C-79 の追加）の確認手順

決定：自分のステータス（在席・外出・欠席・休暇・会議中）を、アバターメニューを開かずに、ヘッダーのボタンから直接切り替えられる。アバターメニュー内の切り替えとプロフィール（S-19）は残し、3つとも同じ保存関数（`setMyStatus`）を通すので食い違わない。在席のときは戻り予定を持たない。戻り予定は「時:分」だけ受け付ける。

| 確認すること | どこで・どう操作するか | 見えるはずのもの |
| --- | --- | --- |
| ボタンの表示 | 画面上部、検索・通知ボタンの右（アバターの左）を見る | 色つきの丸と「在席」。色は在席＝緑・外出＝黄・欠席＝赤・休暇＝青・会議中＝紫。色だけに頼らず文字も出る |
| 切り替え | ボタンを押す→「外出」を選ぶ | 5つの選択肢のメニューが開き、選ぶと即座に切り替わる。通知が出て、メニューが閉じ、フォーカスはボタンに戻る |
| 戻り予定 | メニュー下部の「戻り予定（任意）」に時刻を入れて、ステータスを選ぶ（または「戻り予定だけ更新」） | ボタンの読み上げ名に「（戻り 13:30）」が付く。在席を選ぶと戻り予定は消える。在席のまま「戻り予定だけ更新」を押すと拒否される |
| 他画面への反映 | 切り替えたあと、社員一覧（S-20）・DM（S-06。上部の「戻り予定」）・プロフィールカード（S-27）を開く | 「外出（戻り 13:30）」のように反映される。S-19 の入力欄にも現在の値が入る |
| 同じ保存関数 | アバターメニューで切り替える／S-19 で保存する→ヘッダーのボタンを見る | ヘッダーの表示が変わる。S-19 の不正な値（試作では通常は起きない）は、表示名も含め何も保存しない |
| キーボード | Tab でボタンへ→Enter で開く→矢印の上下で項目を移動→Esc | 開くと先頭の項目にフォーカス。Esc で閉じてボタンへフォーカスが戻る。時刻の入力欄へは Tab で移る。`role="menu"`、`aria-label="ステータスの変更"` |
| スマートフォン | 幅767px以下にする | ボタンは色つきの丸だけ（文字は読み上げ用に残る）。押すとメニューが開く |

案・未決の点：戻り予定は時刻だけ（日をまたぐ予定・日付は未決定）。ステータスの自動切り替え（時刻到達で在席に戻す等）は再現しない。ヘッダーの切り替えを監査ログに残すかは未決定。

## 操作例

1. `testuser_001` で S-05 の #general に投稿し、「返信」から S-07 を開く。スマートフォンでは返信が全画面になる。
2. `testuser_001` で S-18 から営業部案件を申請し、`testuser_002` で S-29 から承認する。`testuser_004` では内容を閲覧できないことを確かめる。
3. `testuser_001` で案件を終了し、公開申請する。`testuser_002` で内容を審査して承認し、別社員で公開内容を確認する。
4. 公開済み案件を `testuser_002` または `testuser_005` で公開取消し、非参加者への内容表示が即座に止まることを確認する。
5. `testuser_007` で参加者ゼロの終了案件を見つけて再開申請する。`testuser_005` で、審査中の内容の閲覧と参加候補の追加を確かめて承認する。
6. 画面確認で社員を切り替え、部署のお知らせ専用チャンネル・チャンネル・通知・スレッドの権限差を確認する。サイドバーの見出し（会社・自部署・他部署・ダイレクトメッセージ・案件・整理スペース）を押して開閉を確かめる（下の確認手順「サイドバーの開閉（案）」）。
7. `testuser_001` で、チャンネル・メッセージ・添付ファイル・返信・案件・DMを「整理スペースに登録」し、S-33でフォルダに分けて、各行のボタンから元の場所へ戻る。
