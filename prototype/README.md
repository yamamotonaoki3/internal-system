# 全体画面プロトタイプ（Issue #48・#62・#76・#80）

`prototype/index.html` をブラウザで直接開く。ビルド、通信、外部ライブラリは不要。架空の社員・データを使い、変更はブラウザのメモリにだけ保持する。再読み込みで初期状態に戻る。

初期画面は S-01 ホーム（「ようこそ、{表示名}さん」と短い案内だけを表示する）。上部に検索・通知・自分のメニュー、左側（サイドバー）にチャンネル（会社・自部署・他部署）・DM・スレッド・案件・整理スペース・共通（社員一覧）・管理をこの順に配置した（「管理」は最下部の項目で、ロールに応じた項目だけが出る。一般メンバーには出ない。C-116）（会社のワークスペースは1つで、切替はない。C-93）。チャンネルなどの大きな項目は開閉できる（案。下の「サイドバーの開閉」）。画面幅768px未満をスマートフォン表示（下部ナビ5項目とメニュードロワー）、768px以上をパソコン表示とする2段階で、タブレット専用の配置はない。右下の「画面確認」で社員・画面番号・表示状態（読み込み中／データあり／データなし／エラー）を切り替えられ、下書きの確認用ボタンとサイドバーの開閉の確認用ボタンもある。#76 で、確認用ボタンを3つ足した（「無効化の見本の部署（企画部）を追加」「企画部のオーナーを引き継いで異動したことにする（見本）」「ABC の今年の連番を9999にする（見本）」）。オーナー交代・オーナーの異動・9999件の案件はこの試作で再現できないため、状態だけを作る確認用の道具で、業務の操作・手順を決めたものではない。この確認道具は業務ナビではない。#80 では確認用ボタンを増やしていない（「企画部」の見本には、申請中の案件作成の申請 R-201 を1件含める）。権限外の画面は番号から開いても内容を表示しない。

ファイル構成: `index.html`（入口）、`extras.js`（下書き・サイドバーの開閉の保存・入力の長さ・離脱の確認・スレッド一覧・取引先の管理）、`screens.js`（共通レイアウトと各画面）、`admin.js`（部署の作成 S-08・チャンネル招待 S-12・退職処理の申請 S-13・アカウント管理 S-22・部署の一覧 S-24、拠点ラベルの管理と設定、部署の無効化と担当部署の付け替え、確認用の見本の部署）、`organize.js`（個人整理スペース S-33、各画面からの登録、添付ファイルの表示）、`announce.js`（お知らせ専用チャンネルの依頼・緊急削除の申請・直接削除・自分の投稿の編集・削除、S-37、通知。#76）、`app.js`（案件の状態と権限、納期の変更、案件番号の連番と前方一致、保存時の自動整形の関数 `normalizeInput`・`compareKey`、類似件名の判定 `similarCases`）、`style.css`・`shell.css`・`organize.css`。読み込み順は `extras.js` → `screens.js` → `admin.js` → `organize.js` → `announce.js` → `app.js`。

## 権限と案件について反映した合意

単一会社。一般社員と部署オーナーの新規案件申請先は所属部署のみ（有効な社員は必ず部署に所属する。所属なしは退職者で、ログインできない）。全体管理者は部署を選択できる。申請者は承認時に自動参加し、他部署の有効社員も候補にできる。承認者は候補追加のみ可能で、自動参加しない。部署オーナーの自己承認は不可、全体管理者は自己承認可能。却下理由は必須で履歴を残し、再申請は別申請とする。

進行中の内容は参加者のみ閲覧・更新可能。非参加者には件名・状態・部署・進捗の概要だけを表示する。参加者は有効社員を追加・削除できるが最後の1人は外せない。終了時は参加者限定の読み取り専用。参加者の公開申請を部署オーナーまたは全体管理者が承認すると有効な全社員が過去の会話・TODO・資料を閲覧できる。公開審査中のみ権限者に読み取り専用の一時閲覧を許し、その閲覧を監査へ記録する。

公開済みアーカイブは、部署オーナーまたは全体管理者が理由・再認証見本・監査記録を伴う公開取消を行える。案件は終了のまま参加者限定になり、非参加者の管理者も内容を見られなくなる。すでにダウンロードされた情報は回収できない。参加者が残る終了案件は参加者が直接再開でき、参加者ゼロの終了案件は全有効社員が再開申請できる。再開後は過去も含め参加者限定。審査中の公開申請は再開で自動取消する。
