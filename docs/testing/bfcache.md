# 実際の bfcache の復元の確かめの手順書（Issue #342 の 342-A。M0〜M3）

ブラウザの「戻る」で、前の文書が丸ごと戻る場合（bfcache）の守り（設計は[access-loss.md](../design/access-loss.md)の「bfcache の復元の守り」。決定は C-212、判断は[ADR-0038](../adr/0038-bfcache-access-check.md)）を、通常のブラウザで確かめる手順をまとめる。

**状態：まだ行っていない。この文書は手順であり、確かめの結果は書かない。結果は、Issue #342 のコメントに記録する。**

## なぜ別に確かめるのか

自動の E2E（`e2e/bfcache-access-loss.spec.ts`・`e2e-prod/bfcache-access-loss.spec.ts`。[e2e.md](e2e.md)）は、`page.evaluate`の中で`pagehide`・`pageshow`を合成して送る（`isTrusted`は偽）。Playwright は、bfcache による復元を既定で扱えないため、実際の保存・復元は再現できない。合成のイベントで言えるのは、「本番の登録・通信・覆い・文書の置き換えが、実ブラウザでつながっている」ことまでで、次のことは言えない。

- ブラウザが実際に保存・復元した文書で、復元の直後の最初の描画に、中身が出ないこと
- 復元された文書で、守りが、期待どおりの順で動くこと

「戻る」が成功したこと・同じ URL に戻ったこと・ナビゲーションの種類だけでも、合格にしない。

## 守ること

- 製品の保護処理を無効にして、復元を成立させない（保護を外すと、確かめたいものが確かめられない）
- 録画・観測の記録に、本文・入力値・Cookie・認証情報を残さない。記録に出すのは、下の「記録するもの」だけ
- 架空のデータだけを使う（`example.com`のメール・`e2euser_`で始まる社員ID・`[E2E_TEST]`の付いた名前）。実在のデータ・本番のデータを使わない
- 起動したもの（サーバー・ブラウザ）は、確かめが終わったら止め、ポートを解放する。自分が起動したか分からないものは、確認せずに止めない
- E2E・ミューテーションなど、検証用の DB・ポートを使う処理と、同時に動かさない

## M0：環境の確認（M1〜M3 の前に、利用者と確かめる）

次が使える環境かを、先に、利用者と確かめる。**成立するかは、まだ確かめていない**。

- 本番形の配信（ビルド済みの成果物と、`public/_headers`の CSP）で動かせること
- 実際のセッション（本物のログインとサーバーの答え）が動くこと。本番形の E2E は、ログインが 503 になるため、API の応答を差し替えている。**その差し替えを、この確かめの環境が成立した根拠にしない**
- 検証専用の DB が使えること（開発用・本番の DB に向けない）

環境が成立しない場合は、準備の問題として記録し、別の環境の準備を、統括へ返す。342-A に、配信の設定の変更を足さない。

## 準備

1. 専用のシード（`e2e/seeds/bfcache-access-loss.sql`）を、検証専用の DB に流す（E2E の spec が使う形と同じ。`node scripts/db-local.ts test seed-file e2e/seeds/bfcache-access-loss.sql`。検証用の環境`test`だけに向ける）。識別子は、社員ID `e2euser_bfcache342_a`（参加者。戻る人）・`e2euser_bfcache342_b`（案件の作成者。A を外す人）、案件5件、通常のチャンネル1つ（[e2e.md](e2e.md)の該当の行）。ログイン用のパスワードは、既存の架空のログイン用シードの方式に従う（この文書に値を書かない）
2. 通常のブラウザ（拡張機能を無効にしたもの）で、対象の画面（S-17 または S-35）を開く
3. アプリが起動した後に、開発者ツールのコンソールへ、**観測の補助**`e2e/support/bfcache-observer.js`の中身を貼って実行する（製品の成果物には入っていない）。アプリの起動の後に実行するので、補助のリスナーは、守りより後に動き、守りが包みを隠した後の状態を見られる
4. 実行の前に、使うブラウザの版・OS・配信の形態（開発用／本番形）・開発者ツールを開いているか、対象の head のコミットを控える（記録に付ける）

### 観測の補助の使い方

- 記録は、同じタブの`sessionStorage`に置く（文書が替わっても残る）。`window.__bfcache342Observer.dump()`で JSON を取り出し、`clear()`で消す
- 記録するもの：`pagehide`・`pageshow`の`persisted`と`isTrusted`、補助が文書ごとに作る目印（`marker`）と`performance.timeOrigin`（往復の前後で同じ文書かを見る）、リスナーが見た包み（`#root`の直下で`main`を含む要素）の`hidden`・`inert`、包みの`hidden`・`inert`が変わった時刻、ナビゲーションの種類（`navigationType`）と`notRestoredReasons`の理由の名前（取得できれば）
- 記録しないもの：本文・入力値・URL の中身・Cookie・認証情報
- 実際の復元の判定：`pageshow`の`persisted`が真、かつ`isTrusted`が真（ブラウザが発火したもの）、かつ、往復の前後で`marker`・`performance.timeOrigin`が同じ。合成したイベント（`isTrusted`が偽）は、実際の復元に数えない

## M1：資格維持

資格が残っているとき、実際の復元の後に、確かめが終わるまで隠れ、終わったら、入力・画面の状態を保ったまま外れること。

1. 参加者（A）で、S-17 を開く。入力欄に、架空の文字（`[E2E_TEST]`を付ける）を入れる。一覧を縦にスクロールし、フォーカスを入力欄に置く。観測の補助を入れる
2. 別の文書へ移り、通常の「戻る」で戻る。追い出されないよう、実験の間は、同じオリジンの別のタブで、合図（別のタブの喪失）を出さない
3. 合格の根拠：
   - 観測の記録に、`persisted`が真・`isTrusted`が真の`pageshow`があり、`marker`・`performance.timeOrigin`が往復の前後で同じ
   - `pageshow`のとき、リスナーが見た包みが、すでに`hidden`・`inert`になっている（復元の直後に、中身が見えない）
   - 確かめが終わった後だけ、包みが外れ、文書が置き換わらず（`marker`が同じ）、入力・フォーカス・スクロールが戻っている

## M2：資格喪失

離れている間に外されていたとき、実際の復元の後も、中身を出さず、覆ったまま文書が置き換わること。

1. A で S-17 を開き、観測の補助を入れ、別の文書へ移る
2. 別の利用者（B）が、通常の操作で A を案件の参加者から外す
3. A が、通常の「戻る」で戻る
4. 合格の根拠：実際の復元の記録（M1 と同じ）、隠れた包み、覆いの維持、文書の置き換え（`marker`・`performance.timeOrigin`が変わる）。続けて、概要を取得していない文書（S-35 だけを開いていた文書。スレッドの実績だけがある）でも、同じ流れを確かめる

## M3：確認失敗

戻ったときの確かめの通信が失敗したとき、隠したまま失敗の案内と「再試行」が出て、入力が保たれ、通信が戻れば、再試行で外れること。

1. M1 と同じ準備で、別の文書へ移る
2. 戻る前に、開発者ツールのネットワークの設定などで、復元の後の確認の通信（セッションの確認、または案件の概要の取得）を失敗させる
3. 戻る。合格の根拠：実際の復元の記録、隠れた包み、失敗の案内と「再試行」の表示、入力の保持（文書が置き換わらない）
4. 通信を戻して「再試行」を押す。合格の根拠：包みが外れ、入力・画面の状態が戻る
5. 概要が 403 のとき（中身を片付けて、覆ったまま文書が置き換わる。保存していない入力が失われる。保存済みの下書きは消えない）との区別は、自動試験の記録（E2E の E6・単体のテスト）と照らす

## 録画と記録

- 録画は、Chrome の開発者ツール（DevTools）の screencast で撮り、同期した DOM の記録（観測の補助）と組み合わせて、復帰した直後の状態を確かめる
- 録画・観測の記録の**実際の保存先**を、対象の head・日時・ブラウザの版・OS・配信の形態・開発者ツールの有無とともに、Issue #342 のコメントに書く
- 動画は、リポジトリには入れない（保存先のみを書く）

## 実際の復元にならなかった回

- `persisted`が偽だった回は、AC-11 の合格に数えない。理由（取得できれば`notRestoredReasons`）を記録する
- 保護処理を外して、成立させない。自動で観測できなくても、M1〜M3 は、通常のブラウザで行う
- 通常のブラウザでも成立しなければ、言えるのは、イベント処理の接続までである。**復元の直後の最初の描画の保護と、AC-11 の実際の復元の部分は、未確認・未達**とする
- Safari・iOS は、確かめる環境がなく、未確認のまま記録する

## 後始末

- 専用の後始末の SQL（`e2e/seeds/bfcache-access-loss-cleanup.sql`）を流し、出力の`remaining_*`が、すべて 0 になったことを確かめる。識別子だけで絞っており、`e2euser_`全体や`[E2E_TEST]`全体を条件にしない
- 起動したサーバー・ブラウザを止め、ポートが解放されたことを確かめる
- 観測の記録（`sessionStorage`）は、`window.__bfcache342Observer.clear()`で消す
