# 機能5：案件への問い合わせ

案件を作り、関係者がやり取りする。メール検索の代わりになる機能。案件の参加者と専用チャンネルのメンバーは1つで、部署をまたいで参加できる。進行中の内容は参加者限定。終了アーカイブの全社員公開と、審査中の一時閲覧は5-5・5-6で限定して認める。2026-10-21の会話合意を反映した。決定の一覧は[決定記録](decision-register.md)、全体の入口は[要件定義書](../requirements.md)。

## 機能一覧

| # | 機能 | 概要 |
| --- | --- | --- |
| 5-1 | 案件の作成・参加者 | 案件を作り、関係者を参加させる。終了・再開し、終了した案件をアーカイブとして見る。案件番号以外を再編集する（AC-20）。担当部署のオーナーと全体管理者が、案件を論理削除・復元し、全体管理者が物理削除する（AC-21〜AC-24） |
| 5-2 | 案件のやり取り | 案件ごとに投稿・返信・添付をする |
| 5-3 | 案件の作成の申請と承認 | 所属部署がある社員と全体管理者が申請し、承認を経て作成する |
| 5-4 | 案件のTODO | 題名・任意の担当者・完了状態と進捗を出す。参加者なら誰でも追加・編集・削除・完了・完了の取り消しができる。0件は「項目なし」（決定） |
| 5-5 | アーカイブの全社員公開 | 公開申請・審査・取消と、審査中だけの閲覧を扱う |
| 5-6 | 参加者0人の案件の再開申請 | 申請・審査・参加者の再選定を行う |
| 5-7 | 取引先の管理 | 案件に結びつける取引先の一覧（名前とコード）を、全体管理者が登録・変更・無効化する |

## 機能要件

### 5-1 案件の作成・参加者

案件を作り、関係者（複数の部署のメンバー）を参加させる

**受け入れ条件**

- AC-1：案件は、作成を申請し、承認されると作成される（5-3）。案件は、担当部署（必須）を1つ持つ（旧「所属ワークスペース」。C-98）
- AC-2：通常は非参加者に内容を見せず、全社員に、件名・状態・担当部署・進捗・納期に案件番号と取引先名を加えた概要を示す（納期はAC-17、案件番号・取引先はAC-18・AC-19。決定。C-86・C-89）。説明・参加者・メッセージ・TODO項目・添付は見せない。例外は、5-5の承認済み全社員公開アーカイブと、5-5・5-6の審査権限者の一時閲覧だけ。全体管理者・オーナーの通常権限で非参加案件を閲覧できるわけではない。進捗の形式は5-4 AC-4（決定。C-84）、0件は「項目なし」。案件専用チャンネルは通常のチャンネル一覧とチャンネルの参加申請の一覧には出さない（決定。C-83）。
- AC-3：進行中の参加者追加・削除は、その案件の参加者なら誰でもでき、再認証は求めない。自分で退出できるが、最後の有効な参加者は退出・削除できない。外れた人は内容の閲覧権限を失う。異動だけでは案件参加を外さない。TODO担当の記録は5-4 AC-6に従う。
- AC-4：案件の一覧（サイドバーの「案件」の項目。画面S-16）に、「自分が参加する案件」と「すべての案件」の切り替えを置く（決定。Q-38）。「すべての案件」では、参加していない案件はAC-2の概要だけを出す。スレッド一覧は別のサイドバー項目S-35とする（[1-4](01-messaging.md) AC-4）
- AC-5：案件の参加者は、所属する部署に関係なく、案件専用チャンネル（5-2）に入れる（決定。権限表 Q-32。解決した未決定事項：[#31](../requirements.md)）。社員が必ず1つの部署に所属すること（[0-1](00-foundation.md) AC-8）は変わらない。案件専用チャンネルへの参加は、所属ではなく、案件の参加者であることで決まる。サイドバーでは、案件専用チャンネルを「案件」の見出しの下にまとめて置き、案件の一覧画面（S-16）からも開ける。参加者だけが「案件」の見出しの下で見る（決定。C-83）。チャンネルのデータ上の置き場（`channels.department_id`。null＝会社直属）は【未決定】：ワークスペースが会社に1つになったため（C-93）、部署に属さない会社直属のチャンネルとして扱う形が【案】だが、担当部署（`cases.department_id`）との関係（担当部署のオーナーの権限が専用チャンネルに及ばないことの確認を含む）は決定記録に定めがないため、推測で決めない（「未決定事項」[#35](../requirements.md)、Q-42）
- AC-6：案件作成の承認時に、1案件につき1つの非公開専用チャンネルを自動作成する。手動作成や通常の公開チャンネルへの変更は行わない。終了アーカイブの内容の全社員公開は、通常のチャンネル公開設定とは分けて5-5で管理する。
- AC-7：案件の参加者と、案件専用チャンネルのメンバーは、1つにする（決定。権限表 Q-32）。案件に参加者を追加すると、自動でそのチャンネルに入る。参加者を外すと、自動でチャンネルから外れる。チャンネルへの招待・参加の申込・参加の許可は、案件専用チャンネルには要らない。参加者とメンバーの持ち方（どちらを正とするか）は設計の段階で決める（案：データモデル 3.3。設計-8）
- AC-8：案件が終了した後も、案件専用チャンネルと参加者を残し、参加者はアーカイブとして見られる（決定。権限表 Q-36。旧未決定事項 #36）
- AC-9：案件の参加者なら誰でも案件を終了できる。終了した案件はアーカイブとして残る（決定）。終了・再開は再認証の対象にしない（C-81。参加者内の日常業務で、再認証は手間が増えるため）
- AC-10：有効参加者が残る終了案件は、その参加者が直接再開できる。有効参加者0人の終了案件は5-6の申請・承認を経て再開する。再開すると過去も含め参加者限定へ戻り、審査中の公開申請は自動取消とし、審査用閲覧権限も終了する。
- AC-11：終了中はメッセージ・TODO・参加者を読み取り専用とし、投稿・返信・編集・削除・添付・TODO復元・通常の参加者変更は不可。公開・再開の申請と審査は5-5・5-6の範囲で行える。非参加者への内容の公開はAC-2の例外に限る。終了中はリアクションの追加・取り消しもできず、読み取り専用とする。再開すると使える（決定。C-81）。
- AC-12：案件一覧は進行中を基本とし、終了した案件へ切り替えられる。参加中／全案件の切り替えも併用する。参加者限定の案件では非参加者の検索対象は件名と、全社員に見える案件番号・取引先名だけで、概要（件名・状態・担当部署・進捗・納期に案件番号・取引先名を加えたもの）だけを返す（検索できる範囲と、結果に表示する概要の項目は別。納期を結果の概要に含めることは決定。C-87。案件番号・取引先名は決定。C-89）。参加者は件名・メッセージ・添付・TODOなどを検索できる。全社員公開が承認されたアーカイブでは、非参加者も件名・メッセージ・TODO・公開可能な添付ファイル名を検索できる。参加者限定添付のファイル名・内容は検索対象外（C-64・C-65）。
- AC-13：終了・再開のアプリ内通知は3-3に従う。再開時の参加者はAC-16で再選定できる。終了・再開・引き継ぎは、誰が・いつ・どの案件を行ったかと、再開時の参加者の再選定の結果を監査ログに記録する。理由を入力する操作では理由も記録する。監査ログの閲覧は全体管理者のみ（0-6、C-76）（決定。C-81）。
- AC-14：AC-2の閲覧例外に該当しない非参加者には「参加者だけが見られます（非公開）」と表示する。通常の参加依頼・承認機能は作らない。参加者0人の終了案件の再開申請（5-6）は、この通常の参加依頼とは別に認める。
- AC-15：進行中の最後の有効参加者を無効化する際は、全体管理者が有効な後任を指定して引き継ぐ。終了案件は引き継ぎ不要で、有効参加者0人になってよい。引き継ぎ操作のために、非参加の管理者へ会話内容の閲覧権限を追加しない。公開・審査による閲覧はAC-2に従う。
- AC-16：再開時は以前の有効参加者を候補にし、追加・除外できる。再開する本人・申請者は必ず参加し、無効な社員は選べない。確定前に残る人・追加する人・外れる人と、過去情報も共有される旨を表示する。申請による再開は承認者も同じ情報を確認する。TODO担当の扱いは5-4 AC-6に従う。
- AC-17：案件に、任意の納期（日付）の項目を1つ設ける。入力は任意で、設定しなくてもよい。納期は、全社員が、すべての案件について、案件の詳細画面（S-17）と案件の一覧（S-16）で見られる（オーナー・全体管理者も同じ）。参加していない社員にも見せるのは、手の空いた社員が、納期の近い案件から優先して手伝えるようにするためである。納期はAC-2の非参加者向けの概要に含める。説明・参加者・メッセージ・TODO項目・添付を見せない決定はAC-2のとおり変えない（決定。C-86。C-85の「参加者だけが見られる」を改めた）。通知や、期限切れ・間近の警告は付けず、表示だけとする。案件の納期は案件自体の項目で、TODOの期限（5-4 AC-5で入れないと決定）とは別である（決定。C-85）。納期を変更できるのは、案件の参加者なら誰でもとする。納期の変更は監査ログに残す（変更前・変更後・変更者・日時）。通知は付けず（C-85のまま）、画面での履歴表示はしない。入力できる日付は今日以降だけとし、過去の日付は入力できない。入力済みの納期が過ぎている場合は、そのまま表示する（エラーにしない）。終了した案件でも納期を表示する。終了中は納期の変更はできない（決定。C-117。終了中の読み取り専用は5-1 AC-11・C-81参照）。納期は、一度設定した後に、未定（空）に戻せる。納期の「今日」は日本時間（JST）で、サーバー側が判定する（決定。C-120）。未決定：案件の作成・編集画面での入力欄の細部
- AC-18：案件には、承認されたときにシステムが自動で付ける案件番号がある。形式は `ABC-261024-0001`（15文字）で、先頭の英大文字3文字は取引先コード、次の6桁は案件が作成された年月日の `YYMMDD`（西暦の下2桁。承認された日）、末尾の4桁はその取引先のその年の連番（取引先ごと・年ごとに数え、毎年1月1日に0001から数え直す）。`英大文字3文字-数字6桁-数字4桁`（正規表現の例：`^[A-Z]{3}-\d{6}-\d{4}$`）以外の形では登録できない。利用者は入力できず、発行後は変更できない。案件を削除・終了しても同じ番号を再利用しない（論理削除でも物理削除でも再利用せず、物理削除した案件の番号は欠番として残す。AC-22・AC-23。C-123）。申請しただけの案件・却下された案件には番号を付けない（決定。C-89）。同じ取引先・同じ年の連番が9999を超えたときは、その日の承認をエラー（`409：CONFLICT`）にし、翌日以降に承認する。番号の形式（15文字）は変えない（決定。C-117）
- AC-19：1つの案件に結びつく取引先は1社だけで、案件の申請時に取引先の一覧（5-7）から選ぶ（必須。5-3 AC-11）。案件の一覧（S-16）・詳細（S-17）・検索結果（S-15）に、案件番号と取引先名を並べて表示する。非参加者向けの概要にも案件番号と取引先名を出す（取引先名とコードは全社員に見える。AC-2）。案件番号でも取引先名でも検索できる（4-2 AC-3。案件番号の検索は前方一致で、前後の空白を除き、大文字小文字は区別せず、ハイフンなし（`ABC261024`）の入力も一致させる）（決定。C-89・C-117・C-120）。取引先を無効にした後も、既存の案件では取引先名をそのまま表示し、「（無効）」の印を付ける。この印は、申請中の案件作成の申請（S-29、S-16の「自分の申請」）にも付ける（決定。C-117・C-120）
- AC-20：案件番号以外は、作成後に再編集できる（件名・説明・納期・参加者・TODOほか。参加者・TODO・納期の既存の規則は、それぞれAC-3・5-4・AC-17のまま）（決定。C-122）。①取引先は変えられない（案件番号の先頭の取引先コードと一致を保つため）。間違えたときは、その案件を削除（AC-21〜AC-23）して、正しい取引先で申請し直す。担当部署は、通常の編集では変えず、既存のとおり部署の無効化の前の付け替え（[2-1](02-workspace-channel.md) AC-14）で変える。②編集できるのは、案件の参加者なら誰でも。担当部署のオーナーと全体管理者は、参加しなくても編集できる。③終了中の案件は編集できない（再開してから編集する。AC-11・C-81）。④編集は再認証なしで、監査ログに残す（変更前・変更後・変更者・日時）。⑤件名の編集にも、自動整形（[5-3](#5-3-案件の作成の申請と承認) AC-13）と、似た案件の警告（5-3 AC-14。細部は【案】のまま）を適用する。**未決定**：編集を他の参加者へ通知するか、担当部署のオーナー・全体管理者が非参加のまま編集したことの見せ方（画面・監査ログの項目）
- AC-21：案件は、担当部署のオーナーと全体管理者が管理できる。管理には、AC-20の編集と、削除（AC-22・AC-23）を含む。担当部署のオーナーの範囲は、自部署が担当部署の案件だけで、他部署が担当の案件は全体管理者だけが管理する。管理者としての権限（参加しなくても編集・削除できる権限）は、自部署が担当する案件に限る（オーナーであっても、担当部署でない案件では管理者として編集・削除できない）。ただし、参加者としての編集の権限は、担当部署を問わずAC-20に従う（他部署の案件に参加しているオーナーも、参加者として編集できる）。管理するために、案件の参加者になる必要はない（ただし、非参加者に内容を見せる決まり（AC-2）は変わらない。管理操作で内容を見せるかは**未決定**）（決定。C-123）
- AC-22：案件の論理削除（非表示）は、担当部署のオーナーと全体管理者ができる。再認証を求め、理由は任意（最大の文字数は**未決定**）。論理削除した案件は、一覧・検索に出なくなる。メッセージ・TODO・添付・参加者・監査ログは残る。案件番号は再利用しない。終了中の案件も削除できる。論理削除した案件は、全体管理者向けの「削除済み」の画面（[画面一覧](screens.md) S-38。置き場所は**未決定**）で見られる。復元できるのは、全体管理者と、その案件を削除した担当部署のオーナーで、物理削除するまで残る（保持期間の自動削除は設けない）（決定。C-123）
- AC-23：案件の物理削除は、全体管理者だけができる。先に論理削除してからでないとできない。再認証と理由（必須）を求める。元に戻せない。案件の中身（メッセージ・TODO・添付・参加者）も全部消す。案件番号は欠番として残し、再利用しない。監査ログには「削除した」事実と案件番号を残し、監査ログ自体は消さない（決定。C-123）。案件専用チャンネルの扱い（案件の削除との連動）は**未決定**
- AC-24：案件の削除についての、決まっていないこと。削除した後の通知、他の機能（検索・未読・通知・整理スペース・スレッド・整理スペースの登録）への影響、削除済みの一覧の絞り込み・並び順、削除した担当部署のオーナーが復元するときの入口は、**未決定**とする（決定記録 C-123）。この削除の規則は案件とチャンネルだけに適用し、メッセージの削除（[1-3](01-messaging.md)。本文を隠す非表示）と、部署（[2-1](02-workspace-channel.md) AC-14。無効化だけで削除はしない）の規則は変えない

### 5-2 案件のやり取り

案件ごとに、参加者同士が投稿・返信する。案件のやり取りは、チャンネルと同じ仕組み（案件専用チャンネル）で行い、メッセージング（機能1）の仕組み（スレッド・添付・検索）をそのまま使う。文書・画像・動画を添付できる

**受け入れ条件**

- AC-1：参加者は案件に投稿・返信できる
- AC-2：添付は機能[1-6](01-messaging.md)と同じ規則に従う
- AC-3：参加者はすべての添付を閲覧・取得できる。審査中は承認権限者が既存の一時閲覧権限で添付を確認できる。承認済み全社員公開アーカイブでは、「全社員公開アーカイブで公開できる」として添付されたファイルだけを非参加者に見せ、参加者限定のファイルはファイル名・内容を隠して「参加者限定の添付」と表示する（C-64）。
- AC-4：案件のやり取りは案件専用チャンネルで行い、返信（スレッド。[1-4](01-messaging.md)）・添付（[1-6](01-messaging.md)）・検索（[4-1](04-search.md)・[4-2](04-search.md)）はチャンネルと同じ仕組みをそのまま使う（決定）
- AC-5：専用チャンネルは非公開として自動作成し、通常のチャンネル作成・公開変更の操作は使わない。終了アーカイブを全社員公開する場合だけ、5-5で内容の閲覧対象を広げる。
- AC-6：専用チャンネルへの通常参加は案件の参加者だけで、所属部署は問わない。追加・削除は案件参加と同期し、通常のチャンネル招待・申込・許可は使わない。通常のチャンネル一覧とチャンネルの参加申請の一覧には出さず（C-83）、概要は別に表示する。内容の全社員公開・審査用一時閲覧は5-1 AC-2の例外に限り、通常の参加者へ自動追加しない。
- AC-7：案件画面に、その案件のメッセージへ添付されたファイルの一覧を置き、一覧から元のメッセージへ移動できる。ファイルは元メッセージに結び付けたまま二重保存しない。一覧の公開範囲は5-1 AC-2とC-64に従い、公開承認済みアーカイブでも公開可能とされたファイルだけを非参加者に表示する（C-62・C-64）。
- AC-8：案件への添付ごとに、添付時に全社員公開アーカイブで公開できるか参加者限定にするかを選ぶ。初期値は参加者限定とする。公開可能の選択は即時公開を意味せず、案件アーカイブの全社員公開が承認されるまでは参加者だけが閲覧できる。審査中は承認権限者が既存の一時閲覧権限で確認できる。添付後に公開可否を変更する方法は未決定（C-64）。

### 5-3 案件の作成の申請と承認

所属部署がある社員と全体管理者が申請し、承認後に案件を作成する。案件は担当部署（必須）を一つ持つ（C-98）。却下・取り下げは履歴を残す。

**受け入れ条件**

- AC-1：一般社員・オーナーが選べる担当部署は自分の所属部署のみ。所属なしの社員は申請できない。全体管理者は全部署から選べる（C-02・C-98）。会社のワークスペースは担当部署にしない（担当部署は部署から選ぶ）。
- AC-2：誰が申請しても、承認されるまで案件は作成されない。承認されると案件が作成され、案件専用チャンネルも自動でできる（5-1 AC-6）。このとき案件番号を自動で付ける（5-1 AC-18。C-89）
- AC-3：承認できるのは、案件の担当部署のオーナーか、全体管理者のうち、誰か1人（自分の申請の扱いはAC-4）。全体管理者は、オーナーに任命された部署に限らず、すべての部署の案件を承認できる。メンバーは承認できない。承認者は、申請者の所属ではなく、案件の担当部署で決まる（その部署のオーナー、または全体管理者。C-98）。承認・却下に再認証は求めない（C-81）
- AC-4：メンバー・オーナーは、自分の申請を承認できない。オーナー自身が申請した案件は、全体管理者が承認する。全体管理者に限り、自分の申請を自分で承認できる（決定。権限表 P-1。全体管理者は1人で確定しているため。チャンネル作成の M-1・O-5 と同じ扱い）。オーナーが全体管理者を兼ねている場合も、全体管理者として自分で承認できる（導いた内容）

- AC-5：申請者は承認時に自動参加する。他部署を含む有効社員を追加候補に指定できる。承認者は候補の追加だけ可能で、候補を外す必要があれば理由付きで却下する。承認者は自動参加しない。
- AC-6：却下理由を必須とし、履歴を残す。前後の空白を除いて1〜200文字とし、空欄または上限超過では却下できない（チャンネル作成申請の却下理由 C-54 の規則を案件作成申請にも適用。決定。C-90・C-91）。申請者は内容を修正し、元の申請を参照する別の申請として再申請できる。
- AC-7：申請中は内容を直接編集せず、本人が取り下げて修正・再申請する。取り下げ履歴を残し、取り下げ後は承認できない。
- AC-8：申請者無効化・異動で申請を自動取消し、履歴を残す。全体管理者の部署変更は取消の対象外。追加候補の無効化は承認を止め、取り下げ・修正・再申請を求める。候補の異動だけなら候補のままとする。
- AC-9：オーナー交代後は新オーナーが審査を引き継ぎ、前オーナーは承認できない。AC-4の自己承認制限は維持する。
- AC-10：案件の作成画面の件名欄の近くに、注意書き「件名は参加していない人にも見える場合があります。機密情報を書かないでください」を出す（決定。C-83。文言は案で、実装段階で調整できる）。公開前や参加者限定の案件でも、件名の見える範囲に合わせて文言は変えない（5-1 AC-2）。
- AC-11：案件の申請では、取引先を取引先の一覧（5-7）から選ぶ（必須）。社内の案件には予約コード `INT`（社内）の取引先を選ぶ。案件番号は承認されたときに付き（5-1 AC-18）、申請中・却下・取り下げ・自動取消の申請には付けない。無効にした取引先は選べない（導いた内容）（決定。C-89・C-117）。取引先を無効にした後の「（無効）」の印は、申請中の申請にも付ける（決定。C-120）。
- AC-12：案件の件名は前後の空白を除いて1〜100文字、説明は2,000文字までとする（決定。C-90）。長さの検査は自動整形後の文字数で行う【案】（AC-13）。
- AC-13：件名（自由入力）の表記揺れを防ぐため、保存するときに自動で整形する（決定。C-121）。整形の対象は、案件の件名、取引先名、チャンネル名、部署名、TODOの題名。整形の内容は【案】：全角の英数字を半角にする、連続する空白を1つにする、前後の空白を除く、記号（ハイフン・長音・波ダッシュなど）を統一する。日本語の文字の変換（半角カナ→全角など）の範囲は**未決定**。
- AC-14：同じ取引先の中に、似た件名・同じ件名の案件があるときは、申請の前に「似た案件があります」と警告する。警告だけで、申請・承認は止めない【案】。案件番号（5-1 AC-18）が一意なので、件名の重複は禁止しない。類似判定の基準は**未決定**。警告の実施は【案】で、組み立て式にしない点（AC-15）は決定（C-121）。
- AC-15：件名は「取引先名＋案件の種別＋自由入力」で組み立てる方式にしない。件名は自由入力のままとし、案件の種別の一覧は持たない（決定。C-121）。

### 5-4 案件のTODO

案件の詳細に、その案件のTODOの項目と進捗を出す（新機能）。TODOの項目は、題名・担当者・完了か未完了を持つ。進捗は、完了した項目の数÷項目全体の数で表す

**受け入れ条件**

- AC-1：案件の詳細に、TODOの項目の一覧が出る。項目は、題名・担当者・完了か未完了を持つ。完了の項目と未完了の項目は、一覧で区別して見分けられる
- AC-2：進行中の参加者は題名を入力してTODOを追加でき、未完了で一覧に出る。非参加者は追加不可。TODOの閲覧は5-1 AC-2の範囲に従う。題名は1〜100文字とする（決定。C-90）。
- AC-3：案件の参加者なら誰でも、未完了の項目を完了にできる。完了にした項目は、完了として一覧に出る
- AC-4：案件の詳細に、進捗（完了数÷全体の数）が出る。表示の形式は「完了数/全体数」の数字と進捗バーを併用する（例：項目が5件で2件が完了なら「2/5」とバー）。パーセント表示は出さず、数字を正とする。削除済みのTODOは、全体数にも完了数にも含めない（決定。C-84）。項目が0件のときは進捗を出さず「項目なし」と出し、「0/0」「0%」は出さない（決定。権限表 Q-35）
- AC-5：期限・優先度・通知は、今回は入れない（決定）
- AC-6：現在の担当は任意で、有効な参加者だけから選ぶ。参加者削除・再開時の除外・無効化で担当者が外れた場合、未完了TODOは現在担当をなしにして、担当した時点の表示名を残す。完了済みTODOは完了時の担当名を残す。有効社員の名前からプロフィール・DMを開けるが、無効社員は「退職者」と表示し、プロフィール・DMへのリンクを出さない。記録は自動期限削除せず、保持によって案件閲覧権限は復活しない（C-24・C-74）。
- AC-7：TODOの項目の追加・編集・削除・完了・完了の取り消しと進捗の変更は、同じ案件を開いている他の参加者の画面に、再読み込みなしで反映される（案。[1-9](01-messaging.md)のリアルタイム更新の対象に含める）
- AC-8：案件の参加者なら誰でも、項目を編集・削除でき、完了を取り消して未完了に戻せる（決定）。編集できるのは題名と担当者（導いた内容）
- AC-9：終了後のTODO・進捗の閲覧は5-1 AC-2の範囲で認める。終了中は追加・編集・削除・復元・完了・完了取消・担当変更は不可。
- AC-10：担当変更の前後・変更日時・変更した人を履歴に残す。履歴の閲覧権限は、そのTODOの閲覧権限と同じとする。
- AC-11：完了時の担当者・完了操作した人・完了日時を記録する。完了取消でも過去の記録を残し、再完了は新しい記録として追加する。
- AC-12：削除したTODOは通常一覧から非表示にし、削除済み一覧から題名・担当履歴・完了記録・削除者と日時を読み取り専用で確認できる。閲覧はそのTODOの閲覧権限者に限る。
- AC-13：進行中の参加者は削除済みTODOを復元でき、復元者と日時を記録する。題名・完了状態・履歴は削除前を引き継ぐ。未完了の担当は現在も有効な参加者の場合だけ戻し、それ以外は担当なしと以前の担当名を残す。完了済みの担当名・完了記録は維持する。
- AC-14：案件の参加者は、案件の詳細画面（S-17）の中で、TODOを展開して、そのTODOの変更履歴（誰がいつ何を変えたか。AC-10・AC-11の担当変更・完了の記録を含む）を見られる。TODOの詳細画面は新設しない（決定。C-84・C-86）。削除済みのTODOは通常の一覧に出さず、AC-12の削除済み一覧（S-17の中で、履歴を読み取り専用で確認する）でだけ見られ、AC-13のとおり復元できる。履歴の閲覧権限はAC-10に従う。
- 補足：他の参加者の画面への即時反映の詳細はAC-7（案）のまま。TODOと履歴は自動期限削除しない（C-74）。削除の方式（物理／論理）とDB構造は未決定（データモデル 設計-10、I-06）。履歴はS-17の中でTODOを展開して見せ、TODOの詳細画面は新設しない（決定。C-86）。

### 5-5 アーカイブの全社員公開

**受け入れ条件**

- AC-1：終了案件の参加者が公開を申請し、担当部署のオーナーまたは全体管理者が承認する（C-98）。承認までは終了済み・参加者限定のままとする。
- AC-2：承認後は有効な全社員が過去の会話・公開可能として添付されたファイル・TODOを読み取り専用で閲覧できる。参加者限定の添付はファイル名・内容を非参加者に見せず、「参加者限定の添付」と表示する。削除・非表示の情報は復元しない（C-64）。
- AC-3：オーナーは自分の公開申請を承認できず、全体管理者が審査する。全体管理者は再認証付きで自己承認できる。承認者は自動参加しない。
- AC-4：審査中だけ承認権限者に内容の一時閲覧を認め、閲覧を監査記録に残す。審査終了・取り下げ・取消やオーナー交代で、その人の審査用閲覧権限を終了する。参加者等の別の根拠による権限は維持する。
- AC-5：却下理由は必須で、履歴を残す。却下後も終了済み・参加者限定のままで、参加者は改めて申請できる。
- AC-6：審査中は本人が取り下げられる。申請者無効化時は自動取消、異動だけなら継続する。取消履歴を残し、ほかの有効参加者も改めて申請できる。
- AC-7：審査中の公開申請は1案件1件。参加者には申請者と審査状況を示す。
- AC-8：オーナー交代後は新オーナーが審査を引き継ぐ。新オーナーが申請者本人なら全体管理者が審査する。
- AC-9：公開済みアーカイブは担当部署のオーナーまたは全体管理者が理由・再認証・監査記録付きで公開取消できる。案件は終了のまま参加者限定に戻る。非参加の管理者も取消後は内容を見られない。既に閲覧・取得された情報の回収はできない。
- AC-10：再開すると過去も含め参加者限定へ戻り、審査中の公開申請を自動取消し、一時閲覧権限も終了する。

### 5-6 参加者0人の終了案件の再開申請

**受け入れ条件**

- AC-1：有効参加者0人の終了案件は、全有効社員が部署を問わず再開申請できる（有効な社員は必ず1つの部署に所属する。C-16・C-102）。申請だけで参加者限定の内容を見せない。全社員公開中なら通常の公開範囲で閲覧できる。
- AC-2：担当部署のオーナーまたは全体管理者が承認する（C-17・C-98）。オーナーの自己承認は不可、全体管理者の自己承認は可。承認者は自動参加しない。承認に再認証は求めない（C-81）。
- AC-3：承認権限者は審査中だけ過去の内容を読み取り専用で閲覧でき、閲覧を監査記録に残す。審査終了・取消・権限喪失で一時閲覧権限を外す。
- AC-4：承認時に申請者を通常の参加者に加え、特別な筆頭権限は与えない。参加候補と確認表示は5-1 AC-16に従う。承認者は候補の追加だけ可能で、除外が必要なら理由付き却下・再申請とする。
- AC-5：却下理由は必須で履歴を残し、申請者は理由を確認・修正し、元を参照する別申請として再申請できる。
- AC-6：本人は審査中に取り下げられる。申請者無効化時は自動取消、異動だけなら継続する。取り下げ・取消履歴を残す。
- AC-7：審査中申請は1案件1件。ほかの社員には審査中であることだけを表示する。却下・取り下げ・自動取消の後は改めて申請できる。
- AC-8：審査中・却下・取り下げ・自動取消では案件の終了状態・公開範囲を変えない。承認時に再開し、過去も含め参加者限定へ戻す。
- AC-9：オーナー交代後は新オーナーが審査を引き継ぐ。前オーナーは承認不可となり、新オーナーが申請者本人なら全体管理者が審査する。
- AC-10：再開申請の理由は必須とする。前後の空白を除いて1〜200文字で、空欄または上限超過では申請できない（却下理由の文字数と同じ規則。C-54。決定。C-87）。
- AC-11：承認前に参加候補（AC-4・5-1 AC-16）が無効化された場合は、承認の画面で無効化された候補を自動で外して表示する。承認者は候補を追加できる（AC-4のまま）。候補が全員いなくなっても、申請者本人が参加者になるので承認できる（決定。C-87）。
- AC-12：案件作成申請（5-3）と共通にする範囲は、「却下理由は必須（AC-5）」「却下後は元を参照する別申請として再申請（AC-5）」「審査中は1案件1件（AC-7）」の3点に限る。承認者の自己承認の扱いなど、案件ごとに違う部分は共通にしない（決定。C-87）。

### 5-7 取引先の管理

案件に結びつける取引先の一覧（マスタ）を、全体管理者が管理する。取引先は取引先名と取引先コードだけを持つ（決定。C-89）。

**受け入れ条件**

- AC-1：取引先の登録・名前の変更・無効化ができるのは全体管理者のみ。オーナー・一般メンバーには、管理の画面もメニューも出ず、APIも使えない。取引先名とコードは全社員が見られる（案件の申請で選び、案件の一覧・詳細・検索結果に出すため）（決定。C-89）
- AC-2：取引先コードは英大文字3文字（案件番号の形式から導いた内容。5-1 AC-18）で、登録時に全体管理者が決める。ほかの取引先と重複するコードは登録できない（決定。C-89）
- AC-3：取引先名は後から変更できる。コードは、その取引先の案件が1件でもできたら変更できない（決定。C-89）
- AC-4：取引先の統合はしない。使わなくなった取引先は無効にし、新しいコードで登録する（`INT` は無効にできない。AC-10）。無効にした取引先は、新しい案件の申請で選べない（導いた内容）。無効にした後も、既存の案件では取引先名をそのまま表示し、「（無効）」の印を付ける。申請中の案件作成の申請にも付ける（決定。C-89・C-117・C-120）
- AC-5：社内の案件には予約コード `INT`（社内）を使う。`INT` を別の取引先のコードにはできず、`INT` のコードも変更できない（導いた内容）（決定。C-89・C-91）
- AC-6：取引先名は1〜50文字（決定。C-89・C-90で案としたものを、C-117で確定）
- AC-7：取引先名は、前後の空白を除いて比較し、大文字・小文字を区別せず重複を認めない。同名の取引先は登録・名前の変更ができない（決定。C-91）
- AC-8：取引先の登録・名前の変更・無効化に、再認証は求めない（決定。C-91）
- AC-9：予約コード `INT`（社内）の取引先は、取引先の初期データとして最初から登録しておく。AC-10の無効化の禁止とコードの扱い（AC-5）を除き、ほかの取引先と同じ扱いとし、名前の変更もできる（決定。C-91・C-92）
- AC-10：予約コード `INT`（社内）の取引先は、無効にできない。S-36の `INT` の行に「無効にする」の操作は出さず、APIで無効化を試みても拒否する（社内の案件を申請できなくなるのを防ぐため）（決定。C-92）
- 未決定：取引先の一覧画面（S-36）の細部

- #1：（決定済み）案件の作成の申請と承認、案件の参加者の追加・削除（5-1・5-3に反映）
- #31：（決定済み）案件専用チャンネルに、他の部署の社員が参加者として入る場合。参加者なら、所属に関係なく入れる（5-1 AC-5〜AC-7、5-2 AC-5・AC-6。権限表 Q-32）
- #35：（一部決定）サイドバー・通常のチャンネル一覧・参加申請の一覧での出し方は決定済み（C-83。5-1 AC-5）。残りは案件専用チャンネルのデータ上の置き場（`channels.department_id`。null＝会社直属。C-93で見直し）と、共通フォルダに出すか
- #36：（決定済み）案件の終了・再開・アーカイブ（5-1 AC-8〜AC-12。権限表 Q-36）。残る細部は #37
- #33：（決定済み）担当・完了・削除・復元と履歴は5-4へ反映済み（保存期間はC-74）。進捗の表示形式・削除済み項目の集計除外・履歴の見せ方はC-84・C-86で決定（5-4 AC-4・AC-14）。削除の方式（物理／論理）とDB構造は設計-10で未決定。
- #37：（決定済み）通知・再開時の参加者再選定・終了・再開・引き継ぎの監査項目・再認証・終了中リアクションは決定済み（C-81）。再開申請の理由の必須、承認前に無効化された候補の扱い、案件作成申請と共通にする範囲も決定済み（5-6 AC-10〜AC-12。C-87）。
- #38：（決定済み）案件の作成画面の件名欄の近くに機密を書かない旨の注意書きを出す（5-3 AC-10。C-83。権限表 Q-38、画面一覧5章 #53）
- #45：（一部決定。C-122・C-123）案件の再編集（5-1 AC-20）、案件の管理・論理削除・復元・物理削除（5-1 AC-21〜AC-23）は決定済み。**未決定**：削除した後の通知、削除済みの画面の置き場所、案件専用チャンネルの扱い、他の機能（検索・未読・通知・整理スペース・スレッド・整理スペースの登録）への影響（5-1 AC-24）。要件定義書7章の番号
- #42：（一部決定。C-85・C-86・C-87・C-117）案件の任意の納期（日付）、全社員がすべての案件で見られること（C-86。C-85の「参加者だけ」を改めた）、通知・警告なしは決定済み（5-1 AC-17）。検索結果の概要にも納期を含める（C-87。参加者限定案件の非参加者が検索できる範囲は件名のまま。案件番号・取引先名はC-89で追加）。変更できる人（参加者なら誰でも）・変更の監査ログ・過去の日付（今日以降だけ入力可）・終了した案件での表示（表示する。終了中は変更不可）はC-117で決定済み。**未決定**：入力欄の細部
- #44：（一部決定。C-89・C-91・C-117）案件番号の形式・自動採番・変更不可（5-1 AC-18）、取引先のマスタと案件ごとの取引先（5-1 AC-19、5-3 AC-11、5-7）は決定済み。連番が9999を超えたときの扱い（その日の承認を409にする）、取引先を無効にした後の案件の表示（名前に「（無効）」の印）、案件番号の検索の方式（前方一致）、取引先名の長さ（1〜50文字）はC-117で決定済み。**未決定**：取引先の一覧画面（S-36）の細部。取引先名の重複不可・取引先の管理に再認証なし・予約コード `INT` は初期データとして最初から登録は、C-91で決定済み（5-7 AC-7〜AC-9）。`INT` の取引先は無効にできない（5-7 AC-10。C-92）
