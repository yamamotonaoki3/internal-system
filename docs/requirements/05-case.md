# 機能5：案件への問い合わせ

案件を作り、関係者がやり取りする。メール検索の代わりになる機能。全体の入口は [要件定義書](../requirements.md)。

## 機能一覧

| # | 機能 | 概要 |
| --- | --- | --- |
| 5-1 | 案件の作成・参加者 | 案件を作り、関係者を参加させる |
| 5-2 | 案件のやり取り | 案件ごとに投稿・返信・添付をする |
| 5-3 | 案件の作成の申請と承認 | メンバー全員が案件の作成を申請し、承認を経て作成する |

## 機能要件

### 5-1 案件の作成・参加者

案件を作り、関係者（複数の部署のメンバー）を参加させる

**受け入れ条件**

- AC-1：案件は、作成を申請し、承認されると作成される（5-3）。案件は、1つのワークスペース（＝部署）に属する
- AC-2：参加者でない人には、案件の存在・内容が見えない（全体管理者・オーナーも、参加していなければ見えない）
- AC-3：参加者の追加・削除は、その案件の参加者なら誰でもできる。再認証は求めない（[0-5](00-foundation.md)の再認証の対象にしない）

### 5-2 案件のやり取り

案件ごとに、参加者同士が投稿・返信する。メッセージング（機能1）の仕組みを使い、文書・画像・動画を添付できる

**受け入れ条件**

- AC-1：参加者は案件に投稿・返信できる
- AC-2：添付は機能[1-6](01-messaging.md)と同じ規則に従う
- AC-3：添付ファイルは参加者だけが取得できる

### 5-3 案件の作成の申請と承認

メンバー全員が、案件の作成を申請できる。誰が申請しても、承認が必要で、承認されると案件が作成される。案件は、1つのワークスペース（＝部署）に属する。却下の扱い（理由など）は未決定

**受け入れ条件**

- AC-1：メンバー全員（オーナー・全体管理者を含む）が、案件の作成を申請できる。申請者の所属ワークスペースと、案件が属するワークスペースが違っていてもよい。案件が属するワークスペースの指定方法は、設計の段階で決める（未決定）
- AC-2：誰が申請しても、承認されるまで案件は作成されない。承認されると案件が作成される
- AC-3：承認できるのは、案件が属するワークスペースのオーナーか、全体管理者のうち、誰か1人（自分の申請の扱いはAC-4）。全体管理者は、オーナーに任命されたワークスペースに限らず、すべてのワークスペースの案件を承認できる。メンバーは承認できない。承認者は、申請者の所属ではなく、案件が属するワークスペースで決まる（そのワークスペースのオーナー、または全体管理者）
- AC-4：メンバー・オーナーは、自分の申請を承認できない。オーナー自身が申請した案件は、全体管理者が承認する。全体管理者に限り、自分の申請を自分で承認できる（決定。権限表 P-1。全体管理者は1人で確定しているため。チャンネル作成の M-1・O-5 と同じ扱い）。オーナーが全体管理者を兼ねている場合も、全体管理者として自分で承認できる（導いた内容）
