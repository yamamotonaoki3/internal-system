# 機能5：案件への問い合わせ

案件を作り、関係者がやり取りする。メール検索の代わりになる機能。案件が承認されると、非公開の専用チャンネルが自動でできる。案件の参加者とチャンネルのメンバーは1つで、所属するワークスペースに関係なく、参加者だけが入れる。全体の入口は [要件定義書](../requirements.md)。

## 機能一覧

| # | 機能 | 概要 |
| --- | --- | --- |
| 5-1 | 案件の作成・参加者 | 案件を作り、関係者を参加させる。終了・再開し、終了した案件をアーカイブとして見る |
| 5-2 | 案件のやり取り | 案件ごとに投稿・返信・添付をする |
| 5-3 | 案件の作成の申請と承認 | メンバー全員が案件の作成を申請し、承認を経て作成する |
| 5-4 | 案件のTODO | 題名・任意の担当者・完了状態と進捗を出す。参加者なら誰でも追加・編集・削除・完了・完了の取り消しができる。0件は「項目なし」（決定） |

## 機能要件

### 5-1 案件の作成・参加者

案件を作り、関係者（複数の部署のメンバー）を参加させる

**受け入れ条件**

- AC-1：案件は、作成を申請し、承認されると作成される（5-3）。案件は、1つのワークスペース（＝部署）に属する
- AC-2：参加者でない人には、案件の存在・内容が見えない（全体管理者・オーナーも、参加していなければ見えない）。案件専用チャンネルも同じで、同じワークスペースの人でも、参加者でなければ入れず、一覧・検索にも出ない（5-2 AC-6）
- AC-3：参加者の追加・削除は、その案件の参加者なら誰でもできる。再認証は求めない（[0-5](00-foundation.md)の再認証の対象にしない）
- AC-4：案件の一覧（サイドバーの「案件」の項目。画面S-16）に、自分が参加者である案件を出す（決定。利用者の言葉では「自分が担当している案件」）。メニューの「スレッド」は作らない（[1-4](01-messaging.md) AC-3）
- AC-5：案件の参加者は、所属するワークスペースに関係なく、案件専用チャンネル（5-2）に入れる（決定。権限表 Q-32。解決した未決定事項：[#31](../requirements.md)）。社員が1つのワークスペースにだけ所属すること（[0-1](00-foundation.md) AC-8）は変わらない。案件専用チャンネルへの参加は、所属ではなく、案件の参加者であることで決まる。サイドバーなどでの出し方と、チャンネルの置き場の所属は未決定（案：サイドバーの「案件」から開く。「未決定事項」[#35](../requirements.md)）
- AC-6：案件の作成が承認されると、その案件の専用チャンネルが自動でできる。1案件につき、チャンネルは1つ。手動では作らない。案件専用チャンネルは、常に非公開（プライベート）のチャンネルである（決定。権限表 Q-32。5-2 AC-5）
- AC-7：案件の参加者と、案件専用チャンネルのメンバーは、1つにする（決定。権限表 Q-32）。案件に参加者を追加すると、自動でそのチャンネルに入る。参加者を外すと、自動でチャンネルから外れる。チャンネルへの招待・参加の申込・参加の許可は、案件専用チャンネルには要らない。参加者とメンバーの持ち方（どちらを正とするか）は設計の段階で決める（案：データモデル 3.3。設計-8）
- AC-8：案件が終了した後も、案件専用チャンネルと参加者を残し、参加者はアーカイブとして見られる（決定。権限表 Q-36。旧未決定事項 #36）
- AC-9：案件の参加者なら誰でも案件を終了できる。終了した案件はアーカイブとして残る（決定）。終了・再開は再認証の対象にしない（導いた内容。[0-5](00-foundation.md)に挙がっていないため）
- AC-10：案件の参加者なら誰でも終了した案件を再開でき、進行中に戻る（決定）
- AC-11：終了中は、メッセージ・TODO・参加者・案件専用チャンネルを読み取り専用にし、投稿・返信・編集・TODOの変更・参加者の追加削除はできない（決定）。メッセージの削除・添付もできない（導いた内容）。非参加者には、終了後も案件の存在・内容は見えない（決定）
- AC-12：案件一覧は進行中を基本とし、「終了した案件」に切り替えられる。終了した案件も検索に出るが、その案件の参加者だけに出る（決定）
- AC-13：終了・再開の記録（監査ログ、終了した人・日時）、通知、終了した案件に新しい参加者を加える必要が出たときの扱い、終了中のリアクションの可否は未決定（未決定。「未決定事項」[#37](../requirements.md)、権限表 Q-37）

### 5-2 案件のやり取り

案件ごとに、参加者同士が投稿・返信する。案件のやり取りは、チャンネルと同じ仕組み（案件専用チャンネル）で行い、メッセージング（機能1）の仕組み（スレッド・添付・検索）をそのまま使う。文書・画像・動画を添付できる

**受け入れ条件**

- AC-1：参加者は案件に投稿・返信できる
- AC-2：添付は機能[1-6](01-messaging.md)と同じ規則に従う
- AC-3：添付ファイルは参加者だけが取得できる
- AC-4：案件のやり取りは案件専用チャンネルで行い、返信（スレッド。[1-4](01-messaging.md)）・添付（[1-6](01-messaging.md)）・検索（[4-1](04-search.md)・[4-2](04-search.md)）はチャンネルと同じ仕組みをそのまま使う（決定）
- AC-5：案件専用チャンネルは、常に非公開（プライベート）である。公開にはできない。案件の作成が承認されると自動ででき、手動では作らない（決定。権限表 Q-32。5-1 AC-6）。通常のチャンネルの作成の申請・承認（[2-2](02-workspace-channel.md)）は使わない
- AC-6：案件専用チャンネルに入れるのは、その案件の参加者だけである（決定。権限表 Q-32）。参加者は、所属するワークスペースに関係なく入れる（5-1 AC-5）。参加者でない人は、同じワークスペースの人でも入れず、チャンネルの一覧・検索にも出ない。全体管理者・オーナーも、参加者でなければ内容を見られない（権限表 Q-15）。参加者の追加・削除に合わせて、メンバーは自動で入る・外れる（5-1 AC-7）。チャンネルへの招待・参加の申込・参加の許可（[2-4](02-workspace-channel.md) AC-2、[2-5](02-workspace-channel.md)）は、案件専用チャンネルには使わない

### 5-3 案件の作成の申請と承認

メンバー全員が、案件の作成を申請できる。誰が申請しても、承認が必要で、承認されると案件が作成される。案件は、1つのワークスペース（＝部署）に属する。却下の扱い（理由など）は未決定

**受け入れ条件**

- AC-1：メンバー全員（オーナー・全体管理者を含む）が、案件の作成を申請できる。申請者の所属ワークスペースと、案件が属するワークスペースが違っていてもよい。案件が属するワークスペースの指定方法は、設計の段階で決める（未決定）
- AC-2：誰が申請しても、承認されるまで案件は作成されない。承認されると案件が作成され、案件専用チャンネルも自動でできる（5-1 AC-6）
- AC-3：承認できるのは、案件が属するワークスペースのオーナーか、全体管理者のうち、誰か1人（自分の申請の扱いはAC-4）。全体管理者は、オーナーに任命されたワークスペースに限らず、すべてのワークスペースの案件を承認できる。メンバーは承認できない。承認者は、申請者の所属ではなく、案件が属するワークスペースで決まる（そのワークスペースのオーナー、または全体管理者）
- AC-4：メンバー・オーナーは、自分の申請を承認できない。オーナー自身が申請した案件は、全体管理者が承認する。全体管理者に限り、自分の申請を自分で承認できる（決定。権限表 P-1。全体管理者は1人で確定しているため。チャンネル作成の M-1・O-5 と同じ扱い）。オーナーが全体管理者を兼ねている場合も、全体管理者として自分で承認できる（導いた内容）

### 5-4 案件のTODO

案件の詳細に、その案件のTODOの項目と進捗を出す（新機能）。TODOの項目は、題名・担当者・完了か未完了を持つ。進捗は、完了した項目の数÷項目全体の数で表す

**受け入れ条件**

- AC-1：案件の詳細に、TODOの項目の一覧が出る。項目は、題名・担当者・完了か未完了を持つ。完了の項目と未完了の項目は、一覧で区別して見分けられる
- AC-2：案件の参加者なら誰でも、題名を入力して項目を追加できる。追加した項目は、未完了で一覧に出る。参加者でない人には、案件の存在・内容が見えないため（5-1 AC-2）、TODOも見えず、追加もできない（全体管理者・オーナーも、参加していなければできない）
- AC-3：案件の参加者なら誰でも、未完了の項目を完了にできる。完了にした項目は、完了として一覧に出る
- AC-4：案件の詳細に、進捗（完了数÷全体の数）が出る。表示の形式は「完了数/全体数」（例：項目が5件で2件が完了なら「2/5」）とする（案）。項目が0件のときは進捗を出さず「項目なし」と出し、「0/0」「0%」は出さない（決定。権限表 Q-35）
- AC-5：期限・優先度・通知は、今回は入れない（決定）
- AC-6：担当者は任意で、なしも認める。選べるのはその案件の参加者だけ。担当者が案件の参加者から外れたら、その人が担当する項目の担当者を「なし」に戻す（決定。権限表 Q-35）
- AC-7：TODOの項目の追加・編集・削除・完了・完了の取り消しと進捗の変更は、同じ案件を開いている他の参加者の画面に、再読み込みなしで反映される（案。[1-9](01-messaging.md)のリアルタイム更新の対象に含める）
- AC-8：案件の参加者なら誰でも、項目を編集・削除でき、完了を取り消して未完了に戻せる（決定）。編集できるのは題名と担当者（導いた内容）
- AC-9：終了後も参加者はTODOと進捗を見られる。終了中は追加・編集・削除・完了・完了の取り消し・担当者の変更はできない（決定。5-1 AC-11）
- 補足：進捗の表示形式（AC-4）と他の参加者への反映（AC-7）は案である（案）。TODOの削除の方式（物理／論理）と履歴は未決定（未決定。[データモデル](data-model.md) 設計-10）
