# 機能3：通知

未読メッセージ・メンションの通知。全体の入口は [要件定義書](../requirements.md)。

## 機能一覧

| # | 機能 | 概要 |
| --- | --- | --- |
| 3-1 | 未読メッセージの通知 | 未読のメッセージがあることを知らせる |
| 3-2 | メンションの通知 | 自分が指名されたことを知らせる |
| 3-3 | 案件の終了・再開の通知 | 有効な参加者へアプリ内で知らせる |
| 3-4 | 申請・審査の通知 | 対応する承認者と申請者へ結果を知らせる |

## 機能要件

### 3-1 未読メッセージの通知

未読のメッセージがあることを知らせる

**受け入れ条件**

- AC-1：未読があるチャンネル・ダイレクトメッセージごとに未読件数を表示する。99件を超える場合は「99+」と表示する
- AC-2：開くと既読になる
- AC-3：部屋の閲覧権限を失った場合、その部屋の未読状態を解除し、その部屋の内容を含む通知を通知一覧から除く

### 3-2 メンションの通知

自分が指名されたことを知らせる

**受け入れ条件**

- AC-1：指名されると、アプリ内で通知される
- AC-2：通知は、指名された本人だけに届く。ただし、そのチャンネルの参加者に限る（公開チャンネルは閲覧だけなら参加不要だが、通知は参加者のみ。未参加の公開チャンネルで指名されても通知しない。C-94、2-3 AC-2）
- AC-3：通知はアプリ内に限り、メールでは送信しない（C-39）。メールアドレスは会社発行アドレスの確認・連絡先表示に使う

### 3-3 案件の終了・再開の通知

**受け入れ条件**

- AC-1：案件の終了・再開を、操作した本人を除く有効な参加者へアプリ内通知する。
- AC-2：再開時の宛先は再選定後に確定した参加者とする。外れた人や、全社員公開を閲覧するだけの非参加者には送らない。
- AC-3：追加・除外そのものの個別通知は設けない。案件終了・再開の通知もアプリ内だけで行い、メールでは送信しない（C-23・C-39）。

### 3-4 申請・審査の通知

**受け入れ条件**

- AC-1：審査が必要な申請が提出されたとき、その申請に対応する承認権限者へアプリ内通知する
- AC-2：審査結果が確定したとき、申請者へアプリ内通知する
- AC-3：申請・審査に関係しない社員には通知しない。メールでは送信しない（C-39）
- AC-4：お知らせ専用チャンネルの編集・削除の依頼と緊急削除の申請（[7-2](07-department.md) AC-6・AC-7）も、アプリ内通知で届ける（C-114）。依頼は投稿者へ、緊急削除の申請は全体管理者へ、承認・却下の結果は申請者へ送る。関係しない社員には通知しない。メールでは送信しない（C-39）。通知の文言は案（画面一覧 S-14）で、未決定

## 関連するAPI

API仕様書は `docs/api/openapi.json`。operationIdは設計の段階で埋める。

| 受け入れ条件 | 必要な操作 | operationId |
| --- | --- | --- |
| 3-1（AC-1〜AC-3） | 未読の状況を取得する・既読にする | 未割当 |
| 3-2（AC-1〜AC-3） | 自分宛てのメンションの通知を取得する | 未割当 |
| 3-3（AC-1〜AC-3） | 案件の終了・再開イベントから対象参加者へ通知し、自分宛て一覧を取得する | 未割当 |
| 3-4（AC-1〜AC-4） | 申請・審査の通知（お知らせ専用チャンネルの依頼・緊急削除を含む）を対象者へ送り、自分宛て一覧を取得する | 未割当 |
