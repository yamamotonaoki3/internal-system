# 機能7：部署の連絡と所属一覧

部署の専用チャンネル、部署のお知らせ（お知らせ専用チャンネル）、社員の一覧。全体の入口は [要件定義書](../requirements.md)。

## 機能一覧

| # | 機能 | 概要 |
| --- | --- | --- |
| 7-1 | 部署の専用チャンネル | 部署を作ると、公開チャンネルの専用チャンネルと、投稿を制限した公開のお知らせ専用チャンネルを自動で作る。専用チャンネルには部署の社員を自動参加させる（C-95・C-108） |
| 7-2 | 部署のお知らせ | 部署ごとのお知らせ専用チャンネルで扱う（専用画面S-21は廃止。C-108）。自部署のオーナーと全体管理者が投稿し、全社員が全部署のものを読める（C-96）。オーナーは他人の投稿を直接編集・削除できず、依頼と緊急削除の申請になる（C-109） |
| 7-3 | 社員の一覧 | 社員の一覧を見て、部署で絞り込む |

## 機能要件

### 7-1 部署の専用チャンネル

部署を作ると、「部署の専用チャンネル」が公開チャンネルとして自動で作られ、その部署の社員が自動で参加する（C-95）。部署の作成は、[2-1](02-workspace-channel.md)と同じ操作である。部署を作れるのは全体管理者のみ（決定）。作成時に、オーナー（別名：部署管理者）を1人指名できる（指名しなければ、作った全体管理者が自動でオーナーになる。2-1）。部署内だけの機密連絡は、非公開チャンネルを通常の申請（オーナー承認。[2-2](02-workspace-channel.md)）で作る（部署の専用チャンネルは公開のままで、他部署の社員が自分で参加できる点も変わらない。C-95・C-109）。専用チャンネルの名前・説明の規則は【未決定】（C-95）。あわせて、部署のお知らせ用に、投稿を制限した公開の「お知らせ専用チャンネル」も自動で作る（7-2、C-108）

**受け入れ条件**

- AC-1：部署の作成と同時に、その部署の専用チャンネルが公開チャンネルとして自動でできる（申請・承認は要らない。C-95）。同時に、部署のお知らせ専用チャンネル（公開。投稿できるのは自部署のオーナーと全体管理者だけ。7-2）も、専用チャンネルとは別に自動でできる（C-108）。お知らせ専用チャンネルの名前・説明の規則と参加（自動参加か）の扱いは【未決定】（C-108(3)）
- AC-2：専用チャンネルは公開チャンネルであり、他の部署の社員も参加せずに読める（2-3、C-94）。投稿・リアクション・未読・通知は参加者だけが使える。部署の社員は自動で参加する。異動したら、旧部署の専用チャンネルから外れ、新部署の専用チャンネルに参加する（0-1 AC-17、C-30・C-95）
- AC-3：部署を作成できるのは、全体管理者のみ。オーナー・一般のメンバーには、作成の画面もメニューも出ず、APIも使えない

### 7-2 部署のお知らせ

部署のお知らせは、専用画面（S-21）ではなく、部署ごとの「お知らせ専用チャンネル」で扱う（C-108。C-78の専用画面は廃止）。お知らせ専用チャンネルは公開チャンネルで、部署の作成時に自動でできる（7-1）。投稿できるのは、自部署のオーナーと全体管理者（全部署）だけ。全社員は参加しなくても全部署のお知らせ専用チャンネルを読める（C-94・C-96）。リアクション・未読・通知・検索は、参加したチャンネルの通常の機能を使う。

編集・削除は、自分の投稿は自分でできる。オーナーは、他人の投稿（他のオーナー経験者・全体管理者の投稿を含む）を直接編集・削除できず、投稿者に編集・削除を「依頼」できる。どうしても緊急に削除が必要な場合は、オーナーが理由を添えて緊急削除を申請し、全体管理者に通知される。全体管理者が承認した場合に限り削除される（C-109。C-107の「オーナーが他人の投稿も直接編集・削除できる」は取り消し）。現時点では、依頼・緊急削除の対象はお知らせ専用チャンネルだけとして書く（ほかのチャンネルへの拡張は【未決定】）。

**受け入れ条件**

- AC-1：お知らせ専用チャンネルに投稿できるのは、自部署のオーナーと、全体管理者だけ。メンバーは、参加していても投稿できない（C-96・C-108）。投稿の制限の持たせ方は【未決定】（C-108(1)）
- AC-2：全社員が、全部署のお知らせ専用チャンネルを、参加しなくても読める（C-94・C-96。C-78の「他部署のお知らせは一般社員に表示しない」を改訂）
- AC-3：投稿の編集・削除は、次のとおり（C-109）。①自分の投稿は、自分で編集・削除できる。②オーナーは、他人の投稿を直接編集・削除できない。投稿者に編集・削除を「依頼」できる。③緊急の削除は、オーナーが理由を添えて緊急削除を申請し、全体管理者に通知される。全体管理者が承認した場合に限り削除される。削除の再認証は、[0-5](00-foundation.md)（投稿の削除）による。**未決定**（C-109(e)）：依頼の宛先・届け方（通知か画面か）、依頼を受けた投稿者が応じなかったときの扱い、依頼の記録（監査）、緊急削除の申請の画面・API・データ、全体管理者が申請者である（オーナー兼任）場合に自分で承認できるか、緊急削除の承認・却下の再認証の要否、削除後のメッセージの表示（[1-3](01-messaging.md)の非表示方式を自動では適用しない）、全体管理者自身の通常の編集・削除権限（C-96・C-107のとおり全部署で維持してよいか）、依頼・緊急削除の対象をお知らせ専用チャンネルだけにするか全チャンネルに広げるか
- AC-4：お知らせの題名と本文の長さの規則は【未決定】（C-108に伴い再検討。旧：題名1〜100文字・本文1〜5,000文字。C-90。題名の有無を含めて、チャンネルのメッセージの規則との関係を決める）。本文のマークダウンは、メッセージと同じ書式に対応する（[1-5](01-messaging.md) AC-2）

### 7-3 社員の一覧

有効で所属部署がある社員の表示名・部署・内線番号・メールアドレス・ステータスを一覧で見る。部署で絞り込める。無効化済み・所属なしのアカウントは一般社員の一覧に表示しない（C-36）。新入社員は登録時に所属部署を指定する。

**受け入れ条件**

- AC-1：ログインしたメンバーは一覧を閲覧できる。一覧には有効で所属部署がある社員だけを表示し、無効化済み・所属なしのアカウントは除く（C-36）。全体管理者向けのアカウント管理一覧（S-22）は別に扱い、再有効化に必要な無効化済みアカウントを表示できる
- AC-2：一覧に表示する項目は、表示名・部署・内線番号・メールアドレス・ステータスのみ（本名は一覧に出さない。AC-4）。メールアドレスはメール作成リンク（mailto）として表示し、内線番号はリンクにせず番号の表示のみとする（C-79）
- AC-3：部署で絞り込める
- AC-4：一覧の表示名を押す（タップする）と、プロフィールカード（画面S-27）で、その人の本名を確認できる（[0-4](00-foundation.md) AC-10。本名を見られるのは、ログイン後の全員。登録は全体管理者が行い、変更は本人の届出を全体管理者が承認する（C-75））
