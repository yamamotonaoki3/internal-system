# 機能7：部署の連絡と所属一覧

部署の専用チャンネル、部署のお知らせ、社員の一覧。全体の入口は [要件定義書](../requirements.md)。

## 機能一覧

| # | 機能 | 概要 |
| --- | --- | --- |
| 7-1 | 部署の専用チャンネル | 部署を作ると、公開チャンネルの専用チャンネルを自動で作り、部署の社員を自動参加させる（C-95） |
| 7-2 | 部署のお知らせ | オーナー（別名：部署管理者）が部署のお知らせを投稿する。全社員が全部署のものを閲覧できる（C-96） |
| 7-3 | 社員の一覧 | 社員の一覧を見て、部署で絞り込む |

## 機能要件

### 7-1 部署の専用チャンネル

部署を作ると、「部署の専用チャンネル」が公開チャンネルとして自動で作られ、その部署の社員が自動で参加する（C-95）。部署の作成は、[2-1](02-workspace-channel.md)と同じ操作である。部署を作れるのは全体管理者のみ（決定）。作成時に、オーナー（別名：部署管理者）を1人指名できる（指名しなければ、作った全体管理者が自動でオーナーになる。2-1）。部署内だけの機密連絡は、非公開チャンネルを通常の申請（オーナー承認。[2-2](02-workspace-channel.md)）で作る。専用チャンネルの名前・説明の規則は【未決定】（C-95）

**受け入れ条件**

- AC-1：部署の作成と同時に、その部署の専用チャンネルが公開チャンネルとして自動でできる（申請・承認は要らない。C-95）
- AC-2：専用チャンネルは公開チャンネルであり、他の部署の社員も参加せずに読める（2-3、C-94）。投稿・リアクション・未読・通知は参加者だけが使える。部署の社員は自動で参加する。異動したら、旧部署の専用チャンネルから外れ、新部署の専用チャンネルに参加する（0-1 AC-17、C-30・C-95）
- AC-3：部署を作成できるのは、全体管理者のみ。オーナー・一般のメンバーには、作成の画面もメニューも出ず、APIも使えない

### 7-2 部署のお知らせ

オーナー（別名：部署管理者）が、自分の部署のお知らせを投稿する。全社員が全部署のお知らせを閲覧でき（C-96）、社員は閲覧のみ。全体管理者は、全部署で投稿・閲覧できる。編集・削除は、自部署のオーナーが自部署の投稿をすべて行える（投稿者本人に限らない。C-107）。お知らせはチャンネルとは分けた専用画面 S-21 に表示する（決定 C-78）。閲覧範囲は AC-2 に従う。

**受け入れ条件**

- AC-1：お知らせを投稿できるのは、自部署のオーナーと、全体管理者だけ。メンバーは投稿できない（C-96）
- AC-2：全社員が、全部署のお知らせを閲覧できる（C-96。C-78の「他部署のお知らせは一般社員に表示しない」を改訂）
- AC-3：お知らせを編集・削除できるのは、自部署のオーナー（自部署の投稿をすべて。投稿者本人に限らない。C-107）と、全体管理者（全部署。C-96）。削除の再認証は、[0-5](00-foundation.md)（投稿の削除）による
- AC-4：お知らせの題名は1〜100文字、本文は1〜5,000文字とする。本文のマークダウンは、メッセージと同じ書式に対応する（[1-5](01-messaging.md) AC-2。決定。C-90）

### 7-3 社員の一覧

有効で所属部署がある社員の表示名・部署・内線番号・メールアドレス・ステータスを一覧で見る。部署で絞り込める。無効化済み・所属なしのアカウントは一般社員の一覧に表示しない（C-36）。新入社員は登録時に所属部署を指定する。

**受け入れ条件**

- AC-1：ログインしたメンバーは一覧を閲覧できる。一覧には有効で所属部署がある社員だけを表示し、無効化済み・所属なしのアカウントは除く（C-36）。全体管理者向けのアカウント管理一覧（S-22）は別に扱い、再有効化に必要な無効化済みアカウントを表示できる
- AC-2：一覧に表示する項目は、表示名・部署・内線番号・メールアドレス・ステータスのみ（本名は一覧に出さない。AC-4）。メールアドレスはメール作成リンク（mailto）として表示し、内線番号はリンクにせず番号の表示のみとする（C-79）
- AC-3：部署で絞り込める
- AC-4：一覧の表示名を押す（タップする）と、プロフィールカード（画面S-27）で、その人の本名を確認できる（[0-4](00-foundation.md) AC-10。本名を見られるのは、ログイン後の全員。登録は全体管理者が行い、変更は本人の届出を全体管理者が承認する（C-75））
