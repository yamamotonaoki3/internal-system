# 機能1：メッセージング

チャンネル・ダイレクトメッセージでのやり取り（投稿・編集・返信・添付・リアクション・メンション・リアルタイム更新）。全体の入口は [要件定義書](../requirements.md)。

## 機能一覧

| # | 機能 | 概要 |
| --- | --- | --- |
| 1-1 | チャンネルのテキストチャット | チャンネルにテキストを投稿する |
| 1-2 | ダイレクトメッセージ | 特定の相手と1対1でメッセージを送る。専用の画面のほか、チャンネル内・社員一覧・プロフィールカードからも始められる |
| 1-3 | メッセージの編集・削除 | 自分のメッセージを編集・削除する |
| 1-4 | 返信 | メッセージに返信する（返信は元のメッセージに紐づけて表示する） |
| 1-5 | マークダウンの表示 | マークダウン記法のメッセージを整形して表示する |
| 1-6 | 添付 | 画像・動画・ファイルを添付する |
| 1-7 | リアクション・スタンプ | メッセージに絵文字のリアクションやスタンプを付ける |
| 1-8 | メンション | メッセージの中で特定のメンバーを指名する |
| 1-9 | リアルタイム更新 | 他の人の投稿を再読み込みなしで反映する |

## 機能要件

### 1-1 チャンネルのテキストチャット

チャンネルに、テキストのメッセージを投稿する

**受け入れ条件**

- AC-1：参加しているチャンネルに投稿できる
- AC-2：参加していない非公開チャンネルには、投稿も閲覧もできない。公開チャンネルは、参加しなくても閲覧できるが、投稿・リアクションは参加者だけができ、未読・通知も参加者だけが対象になる（C-94。[2-3](02-workspace-channel.md)）
- AC-3：投稿者は投稿時点の表示名で表示する。投稿者のアカウントが無効化された後は「退職者」と併記し、プロフィール・DMへのリンクを出さない（C-74）
- AC-4：メッセージ入力欄（チャンネル・スレッド・DMごと）の書きかけは、端末のブラウザに下書きとして一時保存し、その画面に戻ると復元する。サーバーには保存せず、端末をまたぐ継続は対象外。保存先はユーザーごとに分け、同じ端末の別の社員に見えない。下書きには最終編集日時を付け、最終編集から7日で期限切れとし、アプリを開いたときや下書きを読み込むときに端末から物理的に消す。メッセージを送信したとき、利用者が破棄したとき、ログアウトのボタンを押したとき（0-2 AC-8）にも消す。入力内容に変更があるときに画面（モーダルを含む）を離れる前は、確認ダイアログ（「編集を続ける」「破棄して離れる」）を出す（決定。C-82）
- AC-5：メッセージの本文は1〜4,000文字とする。チャンネル・ダイレクトメッセージ・返信・案件のやり取りに共通する（決定。C-90）

### 1-2 ダイレクトメッセージ

特定の相手と1対1でメッセージを送る。不在の相手への用件の伝達（伝言）は、この機能で行う。グループDMと自分自身宛てのDMは設けない（C-55）

**受け入れ条件**

- AC-1：ほかのメンバーにダイレクトメッセージを送れる
- AC-2：やり取りは、当事者だけが閲覧できる
- AC-3：相手が不在でも送れ、相手がログインしたときに読める
- AC-4：ダイレクトメッセージは、専用の画面（画面S-06）で行える。加えて、チャンネル内・社員一覧・プロフィールカード（[0-4](00-foundation.md) AC-10）の「DMを送る」からも始められる（決定。新しい権限は足さず、既存のダイレクトメッセージを送る権限で足りる。権限表 R-24）
- AC-5：相手を選ぶ画面で、候補の相手の部署とステータスが見える（決定。[6-1](06-status.md) AC-4）。サイドバーのダイレクトメッセージの欄に「新しいDM」を置き、そこから相手を選ぶ画面を開ける。社員一覧・プロフィールカード等の「DMを送る」からの開始も残す（C-79）
- AC-6：過去の投稿者は投稿時点の表示名で表示する。投稿者のアカウントが無効化された後は「退職者」と併記し、プロフィール・DMへのリンクを出さない（C-74）

### 1-3 メッセージの編集・削除

自分のメッセージを編集・削除する

**受け入れ条件**

- AC-1：自分のメッセージを編集・削除できる
- AC-2：他人のメッセージは編集できない
- AC-3：編集したメッセージには「編集済み」と表示し、過去の本文の編集履歴は利用者に公開しない（C-57）
- AC-4：削除は再認証の対象（[0-5](00-foundation.md)）。削除の方式は非表示。他人のメッセージ・添付ファイルは、初期値では本人のみ削除できる（他人のものは、どのロールも削除できない）。ロールの編集（[0-7](00-foundation.md)）で、後から他のロールに許可できる（「未決定事項」[#11](../requirements.md)）

### 1-4 返信

メッセージに返信する（スレッド）

**受け入れ条件**

- AC-1：メッセージに返信でき、返信が元のメッセージに紐づいて表示される
- AC-2：元のメッセージが削除されたら本文を隠し、「このメッセージは削除されました」と表示する。既存の返信は残して閲覧できるが、新しい返信は追加できない（C-57・C-59）
- AC-3：個別スレッドは元のメッセージから開き、返信を見る領域（画面S-07）で返信する
- AC-4：サイドバーに「スレッド」の項目を設け、利用者に関係するスレッドの一覧（S-35）を開ける。一覧には、自分が返信した、自分のメッセージに返信があった、自分がメンションされた、のいずれかのスレッドを含める。自分が閲覧できないスレッド（権限を失った部屋など）は出さない。並び順は最後の返信が新しい順。未読の返信があるスレッドに印と件数を出し、スレッドを開くと既読にする。更新は他の未読と同じ方式（部屋ごとの未読と同じ、アプリを開いている間の更新。3-1 AC-1、C-65）で、具体的な更新方式（リアルタイム）は要調査のまま（T-01）（決定。C-91）

### 1-5 マークダウンの表示

マークダウンは必須ではない。マークダウン記法で書いたメッセージは整形して表示できる。記法を使わないテキストだけのメッセージも、そのまま表示できる

**受け入れ条件**

- AC-1：マークダウン記法を使わないテキストだけのメッセージも、問題なく投稿・表示できる
- AC-2：次の記法を投稿後に整形して表示できる：太字、斜体、取り消し線、箇条書き、引用、インラインコード、コードブロック、リンク。入力中のプレビューは設けない（C-58・C-60）
- AC-3：HTMLやスクリプトを書いても実行されない（XSSの対策）。対応ライブラリは実装設計時に選定し、追加前に利用者の承認を得る

### 1-6 添付

画像・動画・ファイルを添付する。ファイルはR2に保存し、権限のある人だけがダウンロード・閲覧できる

**受け入れ条件**

- AC-1：画像・動画・文書を添付できる。1メッセージ最大10ファイルとし、暫定上限は画像10MB・文書25MB・動画100MBとする。形式・上限・アップロード方式はCloudflareの制約を調査したうえで実装前に確定する（C-61・ハーネスC-63）
- AC-2：添付ファイルは、そのメッセージを見られる人だけが取得できる（保存先のURLを誰にでも見える形で公開しない）
- AC-3：送信前に添付一覧とファイルサイズを確認でき、取り消せる。元のファイル名を表示し、保存名はランダムにする。上限超過は保存前に拒否する。1メッセージあたりの合計容量は未決定（[#10](../requirements.md)）
- AC-4：添付を削除した場合、画面上で非表示にし、保存実体の削除を開始する。添付は自動期限削除しない（C-74）。バックアップ保持期間は復旧方式の調査（T-05）で決める

### 1-7 リアクション・スタンプ

メッセージに、絵文字のリアクションと、「いいね」「了解」などのスタンプを付ける

**受け入れ条件**

- AC-1：メッセージに絵文字のリアクションを付けられる
- AC-2：「いいね」「了解」などのスタンプを付けられる
- AC-3：同じリアクションの数と、付けた人が分かる。付けたものは取り消せる
- AC-4：1つのメッセージに付けられるリアクションの種類は20種類までとする。同じ人が同じリアクションを2回は付けられない（決定。C-90）
- 補足：絵文字は標準のUnicode絵文字、スタンプは固定一覧とし、外部APIに依存しない（C-58）。両方を同じ選択画面にまとめる（C-60）。ライブラリは実装前に候補・安全性を調べ、追加前に利用者の承認を得る

### 1-8 メンション

メッセージの中で、特定のメンバーを指名する（@表示名）

**受け入れ条件**

- AC-1：@で候補が出て、特定の社員を指名できる。候補には表示名と部署を表示し、表示名の重複を認める。全員宛て（`@all`・`@channel`・`@here`）の指名は設けない（C-56）
- AC-2：指名された人に通知される（[3-2](03-notification.md)）
- AC-3：そのチャンネルを見られない人には、指名しても内容が届かない。公開チャンネルは参加しなくても閲覧できるが、通知は参加者だけが対象のため、未参加の公開チャンネルで指名されても通知しない（C-94、[2-3](02-workspace-channel.md) AC-2）

### 1-9 リアルタイム更新

他の人のメッセージ・リアクションが、画面を再読み込みせずに反映される

**受け入れ条件**

- AC-1：同じチャンネル・ダイレクトメッセージを開いている他の人のメッセージが、再読み込みなしで表示される（方式はADRで決める。「未決定事項」[#7](../requirements.md)）
- AC-2：案件のTODOの項目の追加・完了と進捗の変更（[5-4](05-case.md) AC-7）も、同じ案件を開いている他の参加者の画面に、再読み込みなしで反映される（案。リアルタイム更新の対象に含める）

## この機能に関わる未決定事項

全件の正は [要件定義書の「7. 未決定事項」](../requirements.md) の表とする。

- #7：リアルタイム更新の方式（Durable Objects・WebSocket等。ADRで決める）
- #10：添付ファイルの上限サイズと許可する形式の一覧
- #11：（決定済み）メッセージ・添付ファイルを削除できる人は初期値では本人のみ、削除の方式は非表示（1-3 AC-4に反映）
- #12：グループのダイレクトメッセージを作るか。全員宛ての指名を作るか
- #13：マークダウンの記法の範囲と、使うライブラリ
- #14：絵文字・スタンプの出どころ
- #41：（一部決定。C-82）下書きの一時保存の対象とする入力欄の厳密な範囲（メッセージ入力欄以外にどこまで含めるか）、複数タブで同じ下書きを編集したときの扱いは未決定
- #25：表示名（本人が変更できる）の重複を認めるか。メンション（1-8）は表示名で指名するため、重複を認める場合の区別
