# 機能2：ワークスペースとチャンネルの管理

ワークスペース（＝部署）の作成、チャンネル（公開・非公開）の作成と承認、招待、オーナーの管理者権限、チャンネルのフォルダ分け、自分専用の整理スペース。ワークスペースと部署は同じもの（1つに統合した）で、社員は1つのワークスペースにだけ所属する。これとは別に、全社員が自動で参加する全社ワークスペースを1つ置く（所属の数には数えない。2-1 AC-5）。全体の入口は [要件定義書](../requirements.md)。

## 機能一覧

| # | 機能 | 概要 |
| --- | --- | --- |
| 2-1 | ワークスペース（＝部署）の作成 | 全体管理者がワークスペースを作る（部署の作成と同じ操作）。作成時に、オーナーを1人指名できる（指名しなければ、作った全体管理者がオーナーになる）。全社員が自動で参加する全社ワークスペース「全体コミュニティ」を、初期データとして1つ置く（オーナーは全体管理者） |
| 2-2 | チャンネルの作成と承認 | チャンネルの作成を申請し、オーナーの承認（1段階）を経て作る。却下には理由を付ける |
| 2-3 | 公開チャンネル | ワークスペースのメンバーが自由に参加できるチャンネル |
| 2-4 | 非公開チャンネル | 招待された人だけが参加できるチャンネル |
| 2-5 | 友人の招待・参加の許可 | 同じ会社の社員（まだどこにも所属していない社員）を招待し、参加を許可する |
| 2-6 | オーナーの管理者権限 | オーナーがメンバーやチャンネルを管理する |
| 2-7 | チャンネルのフォルダ分け | ワークスペースで共通のフォルダを、オーナーが作り、チャンネルを入れる。全員に同じ並びで見える（新機能） |
| 2-8 | 自分専用の整理スペース | 検索などで見つけたチャンネル・ファイル・メッセージを登録し、フォルダで整理する。ほかの人には見えない（新機能。サイドバーの旧「スレッド」の位置） |

## 機能要件

### 2-1 ワークスペース（＝部署）の作成

ワークスペース（＝部署）を新規に作る。作れるのは全体管理者のみ（決定）。ワークスペースと部署は同じもので、ここでの作成は、[7-1](07-department.md)の部署の作成と同じ操作である。作成時に、別の社員を1人だけオーナーに指名できる。指名しなければ、作った全体管理者が自動でオーナーになる（決定）。作ると、そのワークスペースの中に専用チャンネルが自動でできる（7-1）

**受け入れ条件**

- AC-1：ワークスペースを作成できる。ワークスペースの作成は、部署の作成（7-1）と同じ操作である。ワークスペースの作成は、オーナーの指名の有無によらず、重要な操作として再認証される（決定。権限表 P-3。[0-5](00-foundation.md)。失敗すると作成されない）
- AC-2：作成時に、オーナーとして指名できるのは1人だけ。作成時のオーナーの指名も、作成の再認証（AC-1）に含まれる（決定。権限表 P-3。オーナーの任命・交代も再認証）。指名しなければ、作った全体管理者が自動でオーナーになる。指名された社員（全体管理者以外）は、指名と同時に、所属がそのワークスペースに移る（前のワークスペースからは外れる）。全体管理者は所属の制限の対象外のため、この扱いを受けない。作成後のオーナーの交代は、[0-8](00-foundation.md)による
- AC-3：ワークスペースに所属していない人には、その中身が見えない（全社ワークスペースは全員に見える。AC-9。社員は1つのワークスペースにだけ所属する。所属は全体管理者が決める。[0-1](00-foundation.md) AC-8）
- AC-4：ワークスペースを作成できるのは、全体管理者のみ。オーナー・一般のメンバーには、作成の画面もメニューも出ず、APIも使えない。作成は監査ログに残る（案）
- AC-5：全社ワークスペースを1つ置く（決定。権限表 O-1）。全社員が自動で参加する（AC-9）。全社ワークスペースは、社員の「1つのワークスペースにだけ所属する」の所属の数に数えない（所属ではなく、全員が参加する扱い。[0-1](00-foundation.md) AC-8・AC-15）。部署をまたぐ全社員向けのチャンネル（コミュニティなど）は、ここに置く
- AC-6：全社ワークスペースのオーナーは、全体管理者である（任命・交代は行わない。[0-8](00-foundation.md) AC-9）。チャンネルの作成は、2-2のとおり、メンバー全員が申請でき、全体管理者（オーナー）が承認する（2-2 AC-10）
- AC-7：招待・メンバーの削除（所属の解除）・所属なしのルール（2-5 AC-4、2-6 AC-1、[0-1](00-foundation.md) AC-8）は、部署のワークスペースだけに当てはまる。全社ワークスペースからは、誰も外れず、誰も外せない（全員が自動で参加するため。無効化（[0-1](00-foundation.md) AC-9）による場合を除く）
- AC-8：同じ人が、自分の部署のワークスペースと全社ワークスペースの両方で、ロールを持てる（一般メンバーなど。ロールは「ユーザー・ロール・範囲」の割り当てで持つ。[0-9](00-foundation.md)）
- AC-9：全社ワークスペースの扱い（決定。権限表 O-2〜O-6）：①全社ワークスペースは、初期データとして存在する（作成の操作・作成者はない。AC-1・AC-4の作成の対象外）。名前（表示名）は「全体コミュニティ」。投入方法は設計の段階で決める（最初の全体管理者（[0-1](00-foundation.md) AC-10）と同じく、初期データの一つ）。②新入社員の参加と、無効化した社員の扱いは、[0-1](00-foundation.md) AC-15のとおり。③全体コミュニティのオーナーは、AC-6のとおり全体管理者で、任命・交代は行わない（AC-2・[0-8](00-foundation.md) AC-3の「オーナーはワークスペースごとに1人」「任命・交代」の例外。AC-10）。④他の部署のワークスペースは見えない（一覧も中身も）。全体コミュニティは全員に見える。全体管理者は、オーナーを務めるワークスペース（全体コミュニティ、任命されたワークスペース）の中身を見られるが、参加していないチャンネルの内容は見られない
- AC-10：全体管理者は、会社創設者の1人で確定である（決定。権限表 O-7。利用者の言葉：「全体管理者は会社創設者のため、一人で確定です。複数になることはありません。」）。複数の場合は考えない。全体コミュニティのオーナーは、その全体管理者である（AC-6）。この全体管理者は、最初の全体管理者（[0-1](00-foundation.md) AC-10）である。全体管理者の引き継ぎは、[0-10](00-foundation.md) のとおり（決定。権限表 P-2）。引き継ぎで、全体コミュニティのオーナーの権限は後任に付く（0-10 AC-4）
- AC-11：全体コミュニティは、チャンネルではなく、ワークスペースとして置く（決定の記録。権限表 O-1〜O-6）。その中のチャンネルは、全員が作成を申請でき、全体管理者が承認する（2-2 AC-10。権限表 L-1・M-1）。初期チャンネル（最初から置いておくチャンネル）を置くかは未決定（データモデルの設計-7。「未決定事項」[#30](../requirements.md)）

### 2-2 チャンネルの作成と承認

ワークスペースに、チャンネルを新規に作る。公開と非公開を選ぶ。作成には、そのワークスペース（＝部署）のオーナーの承認（1段階）が必要。申請を却下するときは、理由を入力する。理由は履歴に残り、申請者が自分の申請で確認できる

**受け入れ条件**

- AC-1：メンバーが、公開・非公開を選んでチャンネルの作成を申請できる
- AC-2：オーナーの承認が得られるまで、チャンネルとして使えない。承認は、オーナーの承認のみの1段階である（2段階の承認はない）
- AC-3：承認・却下の履歴が残る。承認・却下は、重要な操作として再認証される
- AC-4：却下するときに、理由を入力する欄がある。理由が必須か任意かは未決定（案：必須。「未決定事項」[#24](../requirements.md)）。必須にする場合は、理由が空のままでは却下できない
- AC-5：却下の理由は、承認・却下の履歴に残る（AC-3）
- AC-6：却下された申請の申請者は、自分の申請の一覧で、却下されたことと理由を確認できる。理由を表示するときに、スクリプトが実行されない
- AC-7：承認・却下できるのは、そのワークスペースのオーナーのみ（メンバーはできない）。全体管理者は、オーナーに任命されたワークスペースでは、オーナーとして承認・却下できる。任命されていないワークスペースでは、できない（AC-8の例外を除く）
- AC-8：オーナー自身が申請したチャンネル作成の承認者は、全体管理者である。オーナーは、自分の申請を承認できない。この承認だけは、オーナーに任命されていない全体管理者もできる。ただし、オーナーが全体管理者を兼ねている場合に限り、その人自身が申請したチャンネル作成は、自分で承認できる
- AC-9：第2段階で作るワークスペース範囲のロール（[0-9](00-foundation.md)）は、初期値では承認できない。オーナーが編集で許可した場合だけ、承認できる（第2段階。想定であり未決定）
- AC-10：全社ワークスペース（2-1 AC-5）でも、チャンネルの作成は、メンバー全員が申請でき、全体管理者（そのワークスペースのオーナー）が承認する。全社ワークスペースのオーナー（全体管理者）自身が申請したチャンネル作成は、自分で承認できる（AC-8の兼任時の自己承認と同じ扱い。決定。権限表 O-5）。この場合、AC-7の「オーナーに任命されたワークスペースのみ」の制限は当てはまらない（全社ワークスペースのオーナーは任命ではない。導いた内容）

### 2-3 公開チャンネル

ワークスペースのメンバーなら誰でも参加できる

**受け入れ条件**

- AC-1：ワークスペースのメンバーは、公開チャンネルを一覧で見て、自分で参加できる
- AC-2：ワークスペースのメンバーでない人は参加できない

### 2-4 非公開チャンネル

招待された人だけが参加できる

**受け入れ条件**

- AC-1：招待されていない人には、チャンネルの存在・内容が見えない（一覧にも出ない）
- AC-2：招待できるのは、そのチャンネルの参加者。方法は、メンバーの指名のみ（リンク・コードでの招待は作らない）
- AC-3：招待は、重要な操作として再認証される

### 2-5 友人の招待・参加の許可

ワークスペース・チャンネルに、同じ会社の社員を招待し、参加を許可する。社員は1つのワークスペースにだけ所属し、所属は全体管理者が決めるため、ワークスペースへの招待の対象は、まだどこのワークスペースにも所属していない社員だけである

**受け入れ条件**

- AC-1：招待された社員が、参加を申し込める。チャンネルへの招待は2-4 AC-2のとおり。ワークスペースへの招待ができるのは、そのワークスペースのオーナー（第1段階。全体管理者は、オーナーに任命されたワークスペースのみ）。方法は、メンバーの指名のみ（リンク・コードは作らない）。メンバーはワークスペースへ招待できない
- AC-2：参加は、オーナー（全体管理者は、オーナーに任命されたワークスペースのみ）が許可するまで有効にならない。公開・非公開チャンネルで扱いは変わらない。第2段階で作るワークスペース範囲のロールは、初期値では許可できず、オーナーが編集で許可できる（第2段階。想定であり未決定）
- AC-3：アカウントのない人（社外の人）は招待できない
- AC-4：オーナーが招待・許可の対象にできるのは、まだどこのワークスペースにも所属していない社員（他のワークスペースのオーナーが「メンバーを削除」して所属なしになった社員を含む）だけ。すでに他のワークスペースに所属している社員は招待できない。所属の変更（別のワークスペースへの移動）は、全体管理者だけが行える（[0-4](00-foundation.md) AC-7）
- AC-5：ワークスペースへの招待は、重要な操作として再認証される（[0-5](00-foundation.md)）
- AC-6：この機能の招待・参加の許可は、部署のワークスペースだけに当てはまる。全社ワークスペース（2-1 AC-5）は全社員が自動で参加するため、招待も参加の許可もない

### 2-6 オーナーの管理者権限

ワークスペース（＝部署）のオーナーが、メンバーやチャンネルを管理する。オーナーは、ワークスペースごとに1人だけ（[0-8](00-foundation.md)）

**受け入れ条件**

- AC-1：オーナーだけが、自分のワークスペースについて、メンバーの追加・削除とチャンネルの管理ができる。メンバーの削除は、そのワークスペースからの所属の解除であり、削除された社員は「所属なし」になる（所属なしの社員は、他のワークスペースのオーナーが招待できる。[0-1](00-foundation.md) AC-8）。全体管理者は、オーナーに任命されたワークスペースでだけ、同じ操作ができる。メンバーはできない（できる操作の細かい一覧は未決定。設計の段階で、権限の一覧（[0-7](00-foundation.md)）に落とし込む）
- AC-2：第1段階では、運営を任せる手段は置かず、オーナーが1人で行う。第2段階で、オーナーは、自分のワークスペースの範囲のロールを作って任せられる（[0-9](00-foundation.md)）
- AC-3：AC-1のメンバーの削除（所属の解除）は、部署のワークスペースだけに当てはまる。全社ワークスペース（2-1 AC-5）からは、誰も外せない。全社ワークスペースのオーナーは全体管理者である
- 補足（受け入れ条件ではない）：チャンネルのリーダー（運営を任せる役）を置くかは未決定（権限表 4.2 の O-8）。現状は、チャンネル単位の管理者はなく、チャンネルの運営はオーナーが行う。ロールの範囲に将来「チャンネル」を足せる設計にしておく（[0-9](00-foundation.md)、権限表 3.11）

### 2-7 チャンネルのフォルダ分け

ワークスペースで共通のフォルダを作り、チャンネルを入れて整理する（新機能）。フォルダを作るのはワークスペースのオーナー。ワークスペースの全員に、同じ並びで見える。自分だけのフォルダ（自分専用の整理）は、2-8で行う

**受け入れ条件**

- AC-1：ワークスペースのオーナーが、自分のワークスペースに共通のフォルダを作り、編集でき、チャンネルを入れられる（決定。権限表 R-74）。メンバーはできない（決定）。全体管理者は、オーナーを務めるワークスペース（全体コミュニティ、任命されたワークスペース）に限り、同じ操作ができる（導いた内容。権限表 D-1 と同じ考え方。決定されたのは「ワークスペースのオーナーが作る」まで）
- AC-2：フォルダとその並び順は、そのワークスペースの全員に共通である（決定）。フォルダの中に出るチャンネルは、各自が見られるものだけである（AC-3）
- AC-3：フォルダに入れても、チャンネルの参加の条件・見える範囲は変わらない（導いた内容。参加していないチャンネルや非公開チャンネルは、フォルダに入っていても、その人には出ない。2-3・2-4・権限表 Q-15）。中のチャンネルがその人に1つも見えないフォルダを見せるかは未決定（補足）
- 補足：フォルダの入れ子、1つのチャンネルを複数のフォルダに入れること、フォルダに入れないチャンネルの表示、フォルダの削除、中のチャンネルがその人に1つも見えない（空になる）フォルダを見せるか、フォルダ作成・編集に再認証を求めるかは、決まっていない（未決定。「未決定事項」[#34](../requirements.md)）

### 2-8 自分専用の整理スペース

自分だけが使う整理のスペース（新機能。サイドバーの旧「スレッド」の位置に置く）。検索などで見つけたチャンネル・ファイル・メッセージを登録し、フォルダで整理できる。登録したものから、元の場所や返信へ移動（リンク）できる。ほかの人には見えず、影響しない。案件の一覧（[5-1](05-case.md) AC-4）は、サイドバーの「案件」の項目に残す

**受け入れ条件**

- AC-1：チャンネル・ファイル・メッセージを、自分専用の整理スペースに登録できる。登録の入口は、検索結果（画面S-15）とメッセージのメニューとする（案）。そのほかの入口は未決定（登録できる対象の範囲、登録の入口は未決定。「未決定事項」[#32](../requirements.md)）
- AC-2：登録したものを、自分用のフォルダで整理できる（フォルダを作る・入れる。2-7の共通のフォルダとは別で、自分にだけ見える）。登録したものを自分用フォルダに入れずに置けるか、自分用フォルダの入れ子・削除は未決定（未決定事項 #32）
- AC-3：登録したものから、元の場所や返信へ移動（リンク）できる。チャンネルは、そのチャンネルへ移動する。メッセージは、そのメッセージ（返信は、返信を見る領域）へ移動する。ファイルの「元の場所」（そのファイルを投稿したメッセージか、ファイルの一覧か）は未決定（未決定事項 #32）
- AC-4：登録した内容・フォルダは、本人だけに見える。ほかの人には見えず、ほかの人にも、元のチャンネル・メッセージ・ファイルにも影響しない（決定。権限表 R-75）
- AC-5：登録できるのは、本人が見られるものだけである（導いた内容。参加していないチャンネル・非公開チャンネル・他人のダイレクトメッセージ・参加していない案件は見られないため、登録できない。権限表 Q-15）
- AC-6：登録したものの元が削除された・見られなくなったときの扱いは未決定（「未決定事項」[#32](../requirements.md)）
- 補足：2-8 の未決定の細部は、未決定事項 #32 にまとめた（登録できる対象の範囲、登録の入口、ファイルの元の場所、自分用フォルダに入れずに置けるか、自分用フォルダの入れ子・削除、元が削除されたときの扱い）
