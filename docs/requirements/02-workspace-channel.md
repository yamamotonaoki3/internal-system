# 機能2：ワークスペースとチャンネルの管理

ワークスペースの作成、チャンネル（公開・非公開）の作成と承認、招待、オーナーの管理者権限。全体の入口は [要件定義書](../requirements.md)。

## 機能一覧

| # | 機能 | 概要 |
| --- | --- | --- |
| 2-1 | ワークスペースの作成 | 全体管理者がワークスペースを作る（作成者がオーナーになる。誰がオーナーになるかは #2 で未決定） |
| 2-2 | チャンネルの作成と承認 | チャンネルの作成を申請し、承認を経て作る。却下には理由を付ける |
| 2-3 | 公開チャンネル | ワークスペースのメンバーが自由に参加できるチャンネル |
| 2-4 | 非公開チャンネル | 招待された人だけが参加できるチャンネル |
| 2-5 | 友人の招待・参加の許可 | 同じ会社の社員を招待し、参加を許可する |
| 2-6 | オーナーの管理者権限 | オーナーがメンバーやチャンネルを管理する |

## 機能要件

### 2-1 ワークスペースの作成

ワークスペースを新規に作る。作れるのは全体管理者のみ（決定）。作った人がオーナーになる。全体管理者が作るため、誰がオーナーになるか（作った全体管理者か、別の人を指名できるか）は未決定（「未決定事項」[#2](../requirements.md)）

**受け入れ条件**

- AC-1：ワークスペースを作成できる
- AC-2：作成した人が、オーナーとして管理者の権限を持つ（誰がオーナーになるかは未決定。#2）
- AC-3：ワークスペースのメンバーでない人には、その中身が見えない
- AC-4：ワークスペースを作成できるのは、全体管理者のみ。部署管理者・ワークスペースのオーナー・一般のメンバーには、作成の画面もメニューも出ず、APIも使えない。作成は監査ログに残る（案）

### 2-2 チャンネルの作成と承認

ワークスペースに、チャンネルを新規に作る。公開と非公開を選ぶ。作成には、部署管理者の承認と、管理者の承認が必要。申請を却下するときは、理由を入力する。理由は履歴に残り、申請者が自分の申請で確認できる

**受け入れ条件**

- AC-1：メンバーが、公開・非公開を選んでチャンネルの作成を申請できる
- AC-2：部署管理者の承認、管理者の承認が揃うまで、チャンネルとして使えない（ここでの「管理者」は全体管理者を指すと解釈している。「未決定事項」[#2](../requirements.md)）
- AC-3：承認・却下の履歴が残る。承認・却下は、重要な操作として再認証される
- AC-4：却下するときに、理由を入力する欄がある。理由が必須か任意かは未決定（案：必須。「未決定事項」[#24](../requirements.md)）。必須にする場合は、理由が空のままでは却下できない
- AC-5：却下の理由は、承認・却下の履歴に残る（AC-3）
- AC-6：却下された申請の申請者は、自分の申請の一覧で、却下されたことと理由を確認できる。理由を表示するときに、スクリプトが実行されない

### 2-3 公開チャンネル

ワークスペースのメンバーなら誰でも参加できる

**受け入れ条件**

- AC-1：ワークスペースのメンバーは、公開チャンネルを一覧で見て、自分で参加できる
- AC-2：ワークスペースのメンバーでない人は参加できない

### 2-4 非公開チャンネル

招待された人だけが参加できる

**受け入れ条件**

- AC-1：招待されていない人には、チャンネルの存在・内容が見えない（一覧にも出ない）
- AC-2：招待は、チャンネルの参加者のうち、許可された人だけが行える
- AC-3：招待は、重要な操作として再認証される

### 2-5 友人の招待・参加の許可

ワークスペース・チャンネルに、同じ会社の社員を招待し、参加を許可する

**受け入れ条件**

- AC-1：招待された社員が、参加を申し込める（招待できる人・方法は「未決定事項」[#6](../requirements.md)）
- AC-2：参加は、許可する権限を持つ人が許可するまで有効にならない
- AC-3：アカウントのない人（社外の人）は招待できない

### 2-6 オーナーの管理者権限

ワークスペースのオーナーが、メンバーやチャンネルを管理する

**受け入れ条件**

- AC-1：オーナーだけが、管理の操作ができる（できる操作の一覧は、元の指示が途中で切れているため、「未決定事項」[#2](../requirements.md)で確定する）
