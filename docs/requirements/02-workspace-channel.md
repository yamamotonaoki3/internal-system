# 機能2：ワークスペースとチャンネルの管理

ワークスペース（＝部署）の作成、チャンネル（公開・非公開）の作成と承認、招待、オーナーの管理者権限。ワークスペースと部署は同じもの（1つに統合した）で、社員は1つのワークスペースにだけ所属する。全体の入口は [要件定義書](../requirements.md)。

## 機能一覧

| # | 機能 | 概要 |
| --- | --- | --- |
| 2-1 | ワークスペース（＝部署）の作成 | 全体管理者がワークスペースを作る（部署の作成と同じ操作）。作成時に、オーナーを1人指名できる（指名しなければ、作った全体管理者がオーナーになる） |
| 2-2 | チャンネルの作成と承認 | チャンネルの作成を申請し、オーナーの承認（1段階）を経て作る。却下には理由を付ける |
| 2-3 | 公開チャンネル | ワークスペースのメンバーが自由に参加できるチャンネル |
| 2-4 | 非公開チャンネル | 招待された人だけが参加できるチャンネル |
| 2-5 | 友人の招待・参加の許可 | 同じ会社の社員（まだどこにも所属していない社員）を招待し、参加を許可する |
| 2-6 | オーナーの管理者権限 | オーナーがメンバーやチャンネルを管理する |

## 機能要件

### 2-1 ワークスペース（＝部署）の作成

ワークスペース（＝部署）を新規に作る。作れるのは全体管理者のみ（決定）。ワークスペースと部署は同じもので、ここでの作成は、[7-1](07-department.md)の部署の作成と同じ操作である。作成時に、別の社員を1人だけオーナーに指名できる。指名しなければ、作った全体管理者が自動でオーナーになる（決定）。作ると、そのワークスペースの中に専用チャンネルが自動でできる（7-1）

**受け入れ条件**

- AC-1：ワークスペースを作成できる。ワークスペースの作成は、部署の作成（7-1）と同じ操作である
- AC-2：作成時に、オーナーとして指名できるのは1人だけ。指名しなければ、作った全体管理者が自動でオーナーになる。指名された社員（全体管理者以外）は、指名と同時に、所属がそのワークスペースに移る（前のワークスペースからは外れる）。全体管理者は所属の制限の対象外のため、この扱いを受けない。作成後のオーナーの交代は、[0-8](00-foundation.md)による
- AC-3：ワークスペースに所属していない人には、その中身が見えない（社員は1つのワークスペースにだけ所属する。所属は全体管理者が決める。[0-1](00-foundation.md) AC-8）
- AC-4：ワークスペースを作成できるのは、全体管理者のみ。オーナー・一般のメンバーには、作成の画面もメニューも出ず、APIも使えない。作成は監査ログに残る（案）

### 2-2 チャンネルの作成と承認

ワークスペースに、チャンネルを新規に作る。公開と非公開を選ぶ。作成には、そのワークスペース（＝部署）のオーナーの承認（1段階）が必要。申請を却下するときは、理由を入力する。理由は履歴に残り、申請者が自分の申請で確認できる

**受け入れ条件**

- AC-1：メンバーが、公開・非公開を選んでチャンネルの作成を申請できる
- AC-2：オーナーの承認が得られるまで、チャンネルとして使えない。承認は、オーナーの承認のみの1段階である（2段階の承認はない）
- AC-3：承認・却下の履歴が残る。承認・却下は、重要な操作として再認証される
- AC-4：却下するときに、理由を入力する欄がある。理由が必須か任意かは未決定（案：必須。「未決定事項」[#24](../requirements.md)）。必須にする場合は、理由が空のままでは却下できない
- AC-5：却下の理由は、承認・却下の履歴に残る（AC-3）
- AC-6：却下された申請の申請者は、自分の申請の一覧で、却下されたことと理由を確認できる。理由を表示するときに、スクリプトが実行されない
- AC-7：承認・却下できるのは、そのワークスペースのオーナーのみ（メンバーはできない）。全体管理者は、オーナーに任命されたワークスペースでは、オーナーとして承認・却下できる。任命されていないワークスペースでは、できない（AC-8の例外を除く）
- AC-8：オーナー自身が申請したチャンネル作成の承認者は、全体管理者である。オーナーは、自分の申請を承認できない。この承認だけは、オーナーに任命されていない全体管理者もできる。ただし、オーナーが全体管理者を兼ねている場合に限り、その人自身が申請したチャンネル作成は、自分で承認できる
- AC-9：第2段階で作るワークスペース範囲のロール（[0-9](00-foundation.md)）は、初期値では承認できない。オーナーが編集で許可した場合だけ、承認できる（第2段階。想定であり未決定）

### 2-3 公開チャンネル

ワークスペースのメンバーなら誰でも参加できる

**受け入れ条件**

- AC-1：ワークスペースのメンバーは、公開チャンネルを一覧で見て、自分で参加できる
- AC-2：ワークスペースのメンバーでない人は参加できない

### 2-4 非公開チャンネル

招待された人だけが参加できる

**受け入れ条件**

- AC-1：招待されていない人には、チャンネルの存在・内容が見えない（一覧にも出ない）
- AC-2：招待できるのは、そのチャンネルの参加者。方法は、メンバーの指名のみ（リンク・コードでの招待は作らない）
- AC-3：招待は、重要な操作として再認証される

### 2-5 友人の招待・参加の許可

ワークスペース・チャンネルに、同じ会社の社員を招待し、参加を許可する。社員は1つのワークスペースにだけ所属し、所属は全体管理者が決めるため、ワークスペースへの招待の対象は、まだどこのワークスペースにも所属していない社員だけである

**受け入れ条件**

- AC-1：招待された社員が、参加を申し込める。チャンネルへの招待は2-4 AC-2のとおり。ワークスペースへの招待ができるのは、そのワークスペースのオーナー（第1段階。全体管理者は、オーナーに任命されたワークスペースのみ）。方法は、メンバーの指名のみ（リンク・コードは作らない）。メンバーはワークスペースへ招待できない
- AC-2：参加は、オーナー（全体管理者は、オーナーに任命されたワークスペースのみ）が許可するまで有効にならない。公開・非公開チャンネルで扱いは変わらない。第2段階で作るワークスペース範囲のロールは、初期値では許可できず、オーナーが編集で許可できる（第2段階。想定であり未決定）
- AC-3：アカウントのない人（社外の人）は招待できない
- AC-4：オーナーが招待・許可の対象にできるのは、まだどこのワークスペースにも所属していない社員（他のワークスペースのオーナーが「メンバーを削除」して所属なしになった社員を含む）だけ。すでに他のワークスペースに所属している社員は招待できない。所属の変更（別のワークスペースへの移動）は、全体管理者だけが行える（[0-4](00-foundation.md) AC-7）
- AC-5：ワークスペースへの招待は、重要な操作として再認証される（[0-5](00-foundation.md)）

### 2-6 オーナーの管理者権限

ワークスペース（＝部署）のオーナーが、メンバーやチャンネルを管理する。オーナーは、ワークスペースごとに1人だけ（[0-8](00-foundation.md)）

**受け入れ条件**

- AC-1：オーナーだけが、自分のワークスペースについて、メンバーの追加・削除とチャンネルの管理ができる。メンバーの削除は、そのワークスペースからの所属の解除であり、削除された社員は「所属なし」になる（所属なしの社員は、他のワークスペースのオーナーが招待できる。[0-1](00-foundation.md) AC-8）。全体管理者は、オーナーに任命されたワークスペースでだけ、同じ操作ができる。メンバーはできない（できる操作の細かい一覧は未決定。設計の段階で、権限の一覧（[0-7](00-foundation.md)）に落とし込む）
- AC-2：第1段階では、運営を任せる手段は置かず、オーナーが1人で行う。第2段階で、オーナーは、自分のワークスペースの範囲のロールを作って任せられる（[0-9](00-foundation.md)）
