## 未定の項目

- A：個人情報の扱い（`personal_data`）
- B：管理者機能（`admin`）
- C：重要な操作（決済・公開範囲を広げる・削除・権限の変更など）（`critical_ops`）
- D：複数人での共同作業（同時編集・共有）（`collaborative`）
- E：組織ごとのデータ分離（`org_separation`）
- F：リアルタイムの更新（`realtime`）
- G：止まったときの影響（`availability`）

未定の項目は、決まるまで安全側（扱う・ある・する）として扱う。要件定義の中で利用者に確かめて決める。

## 要件定義で決める機能の項目

認証方式とファイルのアップロードは、機能要件に付随するため、生成のときではなく、ここ（要件定義）で決める。「未定（要件定義で決める）」の項目は、利用者に確かめて決める。

| 項目 | 現在の回答 | 決めるときに従う共通仕様 |
| --- | --- | --- |
| 認証方式（なし・アプリ独自・OIDC・併用） | 未定（要件定義で決める） | C-12〜C-20（認証方式・セッション・MFA など）、F-26（ASVSのレベルの判定） |
| 外部IdP（OIDC・併用のとき） | 未定（要件定義で決める） | C-12〜C-20 |
| ファイルのアップロード（使う・使わない） | 未定（要件定義で決める） | C-63（ファイルのアップロード） |
| 扱うファイルの種類（アップロードを使うとき） | 未定（要件定義で決める） | C-63 |

- 決まったら、`.harness/config.yaml` の `answers`（`auth`・`idp`・`file_upload`・`file_kinds`）とこの文書を更新する。F-26の判定（管理者の機能・共同編集など）も、同じときに見直す
- 認証・アップロードの実装は、ひな形を生成し直さず、アプリの中で、Skill「セキュリティ」などの共通仕様（C-12〜C-20、ASVSのレベルの判定 F-26、C-63）に沿って行う
- 認証を使うときは、利用者とセッションを保存するDBが必要になる（C-16）
