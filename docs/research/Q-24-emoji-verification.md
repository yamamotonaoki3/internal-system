# Q-24 emoji-picker-react 5.1.4 の使い捨て検証

## ① 目的と範囲

- 目的：要判断 Q-24 の残件「ライブラリ選定・承認」のうち、絵文字の選択画面の第一候補 `emoji-picker-react` 5.1.4 について、[調査文書](Q-24-emoji-sticker.md)で「未確認」としていた項目（組み込み、日本語、通信、キーボード操作、アクセシビリティの属性、スマートフォン、CSP、ビルドサイズ、npm audit）を、実際に動かして確かめる（Issue #92）。**この文書は決定ではなく、利用者が本採用を判断するための材料である**。
- 範囲：利用者の承認を得て、リポジトリの外の使い捨てフォルダに、Vite＋React＋TypeScript の小さな検証アプリを作って確かめた。結果だけを、この文書に残す。本番のコード・`docs/tech-stack.md`・リポジトリの `package.json`・`node_modules` は変更していない。検証用のフォルダは、検証の後に削除した。
- 範囲外：スタンプ素材の選定、本採用の手続き（`docs/tech-stack.md` への追記・ADR）、実機（実際のスマートフォン）・スクリーンリーダーでの確認、マークダウンの検証。
- 要件との関係：絵文字は端末の絵文字をそのまま表示（native 表示）し、外部CDNも使わない。スタンプは画像だけで、「絵文字」「スタンプ」は同じ枠の中のタブで切り替える（Q-24 の選定の決定。C-58・C-60）。

## ③ 結論（要点）

**この節は承認前の判断材料（検証時点の記録）であり、この文書自体は決定ではない。承認後の結論と残件（条件・スタンプの素材・CSP・実装での確認）は、[decision-register.md の C-128](../requirements/decision-register.md) を参照。**

- **条件つきで、本採用に進めてよいと考えられる結果だった**。確かめた範囲（Chromium・ヘッドレス）では、日本語の検索・カテゴリ名、外部通信 0 件、キーボード操作、読み上げ用の属性の存在、390px 幅での表示とタッチ操作、React 19.3.0・Vite 8.3.4・TypeScript 6.0.3 でのビルドと実行、`npm audit`（脆弱性 0 件）、CSP のもとでの動作は、いずれも成立した。重大な不具合は見つからなかった。ただし、Tab でグリッドを抜けにくい点は、一覧外への退出方法・必要な操作数・実際の読み上げが未確認のため、アクセシビリティの評価は保留とする（⑤-5）。
- **条件（守らないと動かない・困る点）**：
  1. **CSP には、`style-src` の nonce に加えて、`img-src 'self' data:` が要る**。`img-src` を書かないと（`default-src 'self'` にまかせると）、検索欄のアイコンなど、ライブラリが使う `data:` の画像がブロックされ、コンソールに CSP の違反が出る。`nonce` を渡さず `'unsafe-inline'` もない場合は、スタイルが全部ブロックされ、ピッカーのレイアウトが崩れて使えなくなる（⑤-1）。
  2. **`onEmojiClick` の引数の `imageUrl` は、native 表示でも外部CDN（jsDelivr）のURLの文字列が入っている**。通信はしないが、この値を `<img>` などに使うと外部へアクセスしてしまう。リアクションの値には `emoji`（絵文字の文字）または `unified` を使う（⑤-2）。
  3. **日本語の検索は、「ひらがなの読み」では当たらない語がある**（「ねこ」「いぬ」は0件。「ありがとう」は 2 件）。日本語データの検索語の持ち方による。実用上の影響は、利用者が判断する（⑤-3）。
- **スタンプの作り方**：C-128 で「絵文字とスタンプは同じ枠の中のタブで切り替える」と決定済みのため、**現行の要件に沿う構成は方式B**（枠に「絵文字」「スタンプ」のタブを置き、スタンプ側を自前で作る）である。方式Bは、ライブラリのピッカーと同居できることを確かめた。方式A（`customEmojis`。ライブラリ側にスタンプを登録）も動き、実装が少なく、絵文字と同じ検索・キーボード操作に乗るが、画面上は「スタンプ」がカテゴリの1つとして出て、2つのタブにならない。**方式Aは参考結果であり、採用するには C-128 の変更（利用者の判断と決定記録の更新）が要る**。
- **サイズ**：ビルド後の JavaScript は、ピッカーなしの React のみの構成（gzip 68.58 kB）に対して、ピッカー込みで gzip 約 143 kB 増える（日本語データ込み。内訳は未確認）。検証構成の合計は gzip 約 210 kB で、`docs/requirements/nonfunctional.md` の目標「初回に読み込む JavaScript は圧縮後 200KB 以下」を超える（161KB は、`docs/tech-stack.md` にあるハーネスの試作の参考の実測であり、目標とは別のもの）。ただし、この検証構成は、ピッカーを最初から読み込む1ファイルで、実際の構成ではない。動的読み込みにした後の初回サイズ、本番構成での達成可否、削減の効果は未確認（⑤-4）。
- **未確認で残る重要な点**：スクリーンリーダーでの実際の読み上げ、実機のスマートフォン、日本語の IME（変換中の入力）での検索、Firefox・Safari。本採用の前に確かめるかどうかは、利用者が判断する（⑥）。

### (f) CSP：条件つき

次の3通りの CSP を HTTP ヘッダーで配信し、コンソールの違反を記録した（`script-src` は常に `'self'`。`unsafe-inline` なし）。

| CSP（ヘッダー） | 結果 |
| --- | --- |
| `default-src 'self'; script-src 'self'; style-src 'self' 'nonce-…'`、`EmojiPicker` に `nonce` を渡す | 動く。ただし、**`data:` の画像2件が `img-src`（`default-src` の代わり）でブロックされ、コンソールにエラーが2件出た**（検索欄の虫眼鏡のアイコンと、ツールチップの矢印の SVG。`data:image/svg+xml,…`） |
| 上に `img-src 'self' data:` を足す | **違反 0 件・エラー 0 件。見た目も正常**（検索欄のアイコンあり） |
| `style-src 'self'`（nonce なし、`unsafe-inline` なし） | **スタイルが全部ブロックされ、ピッカーが崩れて使えない**（コンソールに「Applying inline style violates…」が2件。画面は絵文字が左上に並ぶだけ） |

- 結論：`unsafe-inline` なしで動く。必要な設定は、(1) `EmojiPicker` に nonce を渡す、(2) `style-src` に同じ nonce を入れる、(3) `img-src 'self' data:` を足す。スタンプの画像を自サイトの静的ファイルに置けば、`img-src 'self'` で足りる（`data:` の画像は、ライブラリのアイコンのために必要）。
- React の `style` 属性（絵文字の位置などの実行時のスタイル）は、CSSOM 経由のため、`style-src` の nonce で足りた（違反は出なかった）。
- nonce は、HTML を返すたびに変わる値にする必要がある。静的ホスティング（Cloudflare Workers の静的アセット配信）で HTML に nonce を差し込む方法は、この検証では確かめていない（⑥）。`style-src` に nonce を使えない場合は、ハッシュ許可もあるが、未検証。
- nonce の渡し方：検証アプリでは、HTML の `<meta name="csp-nonce">` から読んだ（DOM に出ると、ブラウザが `nonce` 属性の値を隠す仕様のため、`<style nonce="">` のように見えるが、動作は正常だった）。

### (g) リアクション用の絵文字の取り出し：合格（注意あり）

`onEmojiClick` の引数（`EmojiClickData`）を記録した。

- 通常の絵文字（🥰 を選択）：`emoji` が `"🥰"`（native の文字列）、`unified` が `"1f970"`、`unifiedWithoutSkinTone` が `"1f970"`、`activeSkinTone` が `"neutral"`、`names` が日本語の名前の配列、`isCustom` が `false`。
- **`imageUrl` は `https://cdn.jsdelivr.net/npm/emoji-datasource-apple/img/apple/64/1f970.png`（外部CDN）**。native 表示では通信しないが、この値は使わない（⑤-2）。
- カスタム絵文字（スタンプ。方式A）を選択：`emoji` と `unified` は登録した `id`（`"stamp-thanks"`）、`imageUrl` は登録した `imgUrl`、`isCustom` が `true`、`names` が登録した名前。→ リアクションの値を「絵文字は Unicode 文字、スタンプは固定一覧の識別子」（EP-1-12）とする設計に、`emoji`（文字）と `isCustom`・`id` でそのまま使える。
- リアクションバー（`reactionsDefaultOpen`・`reactions` の指定）：よく使う絵文字を並べた帯が出て、クリックで `onReactionClick` が呼ばれた（👍 で `unified` が `"1f44d"`）。バーから全体のピッカーへ展開する動きは未確認。
- スタンプのタブ（方式B。自前）：`<button>` のクリックで、固定一覧の `id`（`"stamp-ok"`）を取り出せた。

## ⑤ 見つかった問題と対処案

1. **CSP**（条件つき）：
   - 問題：nonce なし・`unsafe-inline` なしでは、ピッカーのスタイルが全部ブロックされて使えない。nonce があっても、`img-src` を `default-src 'self'` のままにすると、`data:` の SVG（検索欄のアイコンなど）がブロックされる。
   - 対処案：`style-src 'self' 'nonce-…'`・`img-src 'self' data:` とし、`EmojiPicker` に同じ nonce を渡す。実装時、Skill「security」の CSP の決定と合わせる。画像のスタンプの置き場所を自サイトにすれば、`img-src` はこの2つで足りる。
2. **`imageUrl` が外部CDNのURL**：
   - 問題：native 表示でも、`onEmojiClick` の `imageUrl` に外部CDNのURLの文字列が入る。使うと外部通信と CSP 違反になる。
   - 対処案：リアクションの保存・表示には `emoji`（文字）または `unified` だけを使い、`imageUrl` を使わないルールにする。カスタム絵文字（スタンプ）は `isCustom` と `id` で見分ける。
3. **日本語の検索の取りこぼし**：
   - 問題：「ねこ」「いぬ」のようなひらがなの読みで0件になる。日本語データは、漢字・カタカナ中心の名前と検索語を持つと見られる。
   - 対処案：(a) そのまま受け入れる（漢字・カタカナ・絵文字の名前で探せる）。(b) 検索語を足す（`emoji-picker-react/data` の検索 API と、自前のかなの変換の併用。実装が増える）。(c) 検索の使い方の案内を出す。どれにするかは利用者が決める。「猫」「ネコ」の検索は未確認なので、本採用の前に確かめるとよい。
4. **サイズ**：
   - 問題：増加分が gzip 約 143 kB で、検証構成の合計は gzip 約 210 kB。`nonfunctional.md` の目標（初回に読み込む JavaScript は圧縮後 200KB 以下）を、この構成では超える。tech-stack の「161KB」はハーネスの試作の参考の実測で、目標とは別。
   - 対処案：ピッカーを開くときに読み込む（動的 import。ピッカーを開く操作が必要なので、初回には要らない）。`emoji-picker-react/primitives` の入口の利用（データの遅延読み込み）。どちらも、この検証では計測していない（未確認）。
5. **Tab で絵文字ごとに止まる**：
   - 問題：グリッドの全セルが Tab で止まる状態。キーボードだけで使う人は、Tab でグリッドを素早く抜けられない。
   - 対処案：矢印キーで移動はできるが、一覧の外へ出る方法・必要な操作数・実際の読み上げは確かめていないため、評価は保留とする（C-80 は WCAG 2.1 AA 相当が目標）。本採用後の実装で、実際の読み上げ・操作の確認をしたうえで、このまま使うか判断する。
6. **Esc で閉じる動き**：ライブラリは、ピッカー単体の Esc での閉じる動きを確認できなかった。ポップオーバー・ダイアログの親側で、Esc で閉じてフォーカスをもとのボタンに戻す実装を置いた（今回の検証で動いた）。
7. **スタンプのタブ（方式B）の作り方**：
   - 検証アプリでは、`role="tablist"`・`role="tab"`・`role="tabpanel"` とクリックによる切り替えを自前で作り、絵文字のパネルにライブラリのピッカーを、スタンプのパネルに `<button>` のグリッドを置いた。同居できた（切り替え後も、ピッカーは検索・スクロールが再び使えた。`hidden` で隠すだけなので、ピッカーの状態は保たれる）。
   - 自前部分で必要になるもの：タブの矢印キーでの移動（今回は未実装。Tab とクリックだけ）、フォーカスの管理、スタンプ側の検索（ライブラリの検索欄は絵文字側のみ）、`aria-label` の付与。
   - 方式A（`customEmojis`）では、スタンプの検索（名前での検索は可。「了解」「ありがとう」で当たった。カテゴリ名の「スタンプ」では当たらなかった）、カテゴリのタブ（「スタンプ」。`categories` に `{ category: Categories.CUSTOM, group, name }` を指定）、キーボード操作が、絵文字と同じになる。アクセシビリティの属性も付く（`<img alt>`・セルの `aria-label`）。ただし、画面上は「絵文字」と「スタンプ」の2つのタブではなく、カテゴリの1つ（最後）として出る。C-128 の「同じ枠の中のタブで切り替える」を満たさないため、採用するには C-128 の変更が要る。
8. **`emojiVersion`・`lazyLoadEmojis`**：検証アプリでは `lazyLoadEmojis` を指定したが、native 表示では画像を使わないため、効果は確かめていない。`emojiVersion` は指定していない（native 表示では、README によれば、端末が描けない絵文字を自動で除外する。確かめていない）。
