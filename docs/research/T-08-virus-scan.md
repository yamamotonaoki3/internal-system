# T-08 調査：添付のウイルススキャン方式

- 対象：Issue [#116「ウイルススキャンの方式を調査する」](https://github.com/yamamotonaoki3/internal-system/issues/116)。調査と選択肢の提示まで。採用・要件変更・実装は行わない。
- 調査日：2026-11-07（日本時間）。料金・制約・規約は導入前に再確認する。
- 調査方法：公式文書と提供元の公式ソースコードを読む机上調査。アカウント作成、契約、ファイル送信、API呼び出し試験、EICAR試験、依存追加、本番操作は一切行っていない。

## 1. 結論と推奨（決定ではない）

現行の添付上限を保ったまま比較を続ける第一候補は、**自前のClamAVをHTTPSの認証付き検査サービスとして呼ぶ方式**である。100MBの入力は公開されているエンジンのサイズ制限内であり、検査事業者へのファイル提供を増やさずに構成できる。ただし、別の実行環境・更新・監視が必要で、「無料のソフトなので総費用も無料」ではない。検査済みの内容をR2へ保存する手順、検査用の一時保存を認める範囲、費用・性能は未確認である。[ClamAVの要件][S1]・[設定][S3]

自前運用を避けることを優先し、外部処理と検査用隔離保存を認める場合は、**attachmentAVのURL取得方式**を次候補とする。同期URL取得は200MBまで、非同期は5GBまでという公表値がある。一方、直接バイナリ送信は10MBまでなので、それだけで文書25MB・動画100MBを扱うことはできない。[attachmentAV API定義][S6]

**Cloudflare WAFのMalicious uploads detectionを唯一の検査にする案は、現行条件では推奨しない。** Enterprise有料追加が必要で、要求本文の先頭50MBまでが対象であり、想定しているPro以下・動画100MBを満たさない。[Cloudflare WAF][S10]

どの方式でも検査結果は安全性の保証ではない。ADR-0011の形式検査・安全な配信ヘッダー・認可を継続し、未検査・失敗を正常として扱わない方針を別途決める。

| --- | --- | --- |
| 添付の上限（1-6 AC-1・V-20） | 画像10MB、文書25MB、動画100MB。MBは1,000,000バイト | この値を変えない。アバター2MBも参考として比較する |

| 保存前拒否（V-20、1-6 AC-3） | **上限を超えたファイル**は保存前に拒否 | 感染検査全般の保存前拒否という意味へ広げない |
| 経路（1-6 AC-6・AC-7） | アップロード・配信ともWorkers経由。取得ごとに認可。署名付きURLと `r2.dev` は使わない | 検査用URL・例外の採否も利用者が決める |

**文書間で明示されている範囲に違いがある。** `api-draft.md` のV-20の文言は「上限を超えたファイルは保存される前に拒否する」。`01-messaging.md` の1-6 AC-3も「上限超過は保存前に拒否する」としている。一方、ADR-0011の「Office新形式の中身の検査」選択肢4は「保存後に非同期で検査する：保存前の拒否（V-20）に合わず、要件の変更を伴う」とし、「影響」でも非同期検査によるV-20の見直しを示している。`T-02-recheck.md` 5章の比較も保存後検査を同様に扱っている。

したがって、**サイズ超過の保存前拒否を維持すること**と、**感染検査の時点・検査用の隔離領域への保存可否**を別の決定事項とする。隔離後に超過を見つけて消す方式は、サイズについての現行要件を満たさない。反対に、サイズを保存前に確定検証したうえで感染検査のために隔離する方式については、現行文言だけで採用・禁止を断定しない。ADRの説明との整理を利用者が決め、必要な文書を決定後に揃える。今回の調査では要件を書き換えていない。

### 費用の比較に含めるもの

自前方式は「ホストの月額＋必要な冗長化＋ディスク＋ホスト側の転送＋運用工数」を見積もる。ClamAVの公式推奨はメモリ3GiB以上、CPU 1個・2GHz以上、アプリ用の空きディスク5GiBであり、通常のWorkersの128MBメモリにそのまま載せる案は適さない。[ClamAVの要件][S1]・[Workers制限][S12]

外部方式の公開枠を超えたときは429となり、料金を払えば自動的に無制限に検査されるとは扱わない。ポーリングや利用枠確認も要求枠を使う。[attachmentAVの枠制限][S11] 月間ファイル数・平均サイズ・ピーク・再試行率は未決定なので、円換算や総額を推測しない。

各案に共通して、Workers Paidは基本$5/月と超過要求・CPU従量、R2 Standardは保存$0.015/GB月、Class A $4.50/100万回、Class B $0.36/100万回（無料枠あり）、R2の外向き転送は無料。隔離保存・検査用GET・再試行・検査後のコピーは利用量を増やし得る。外部のホストや検査APIの料金までR2の無料転送に含まれるわけではない。[Workers料金][S17]・[R2料金][S13] Queuesを追加する場合の費用は別途見積もる。

## 4. 上限ファイルを扱えるか（AC-2）

「可能」は公表されている入力サイズの範囲内という意味。全形式で検査が完了すること、速度、安全性、Workersからの経路の動作確認を意味しない。

| 入力/方式 | アバター2MB | 画像10MB | 文書25MB | 動画100MB | 根拠と制約 |
| --- | --- | --- | --- | --- | --- |
| ClamAV（設定を確認した中継） | 範囲内 | 範囲内 | 範囲内 | 範囲内 | 公式設定サンプルは `StreamMaxLength`・`MaxFileSize` の既定100M、`MaxScanSize` 400M。Mは1,048,576バイトなので100,000,000バイトは前二者の100M内。技術上2GB超は不可。実際の採用版・稼働設定・展開制限は未確認。[S3] |
| attachmentAV 同期binary | 範囲内 | 公称上限内・境界未確認 | 不可 | 不可 | 公称10MB、60秒。単位の定義と上限ちょうどの動作は未確認。[S6] |
| attachmentAV 同期form | 範囲内 | **上限ちょうどは不可になり得る** | 不可 | 不可 | ファイル本体ではなく本文10MBからフォームの付加分を引く。[S6] |
| attachmentAV 同期URL | 範囲内 | 範囲内 | 範囲内 | 範囲内 | 公称200MB、60秒。取得元の用意が必要。100MBでの処理時間・取得経路は未確認。[S6] |
| attachmentAV 非同期URL | 範囲内 | 範囲内 | 範囲内 | 範囲内 | 公称5GB。検査対象の取得待ち時間などと最終完了時間は別。R2隔離方式は未承認。[S6] |
| Cloudflare WAF | サイズ範囲内 | サイズ範囲内 | サイズ範囲内 | **全文検査不可** | 要求本文全体の先頭50MBのみ。複数ファイルは枠を共有する。形式等の別制約あり。[S10] |

ClamAVのサイズ上限を上げるだけでは十分ではない。Officeなどのコンテナは展開後合計・階層・ファイル数による制限があり、上限超過を未検査の正常結果と取り違えない設定・結果変換が必要となる。`AlertExceedsMax` と暗号化文書の扱いは導入時に確認する。[ClamAV設定][S3]

WAFは、対象外のテキスト/CSVなど、暗号化ファイル、深い入れ子などにも制約がある。部分検査や未検査が感染なしと同じような値になる場合を防ぐため、結果フラグの設計が必要である。ここから許可形式を変更することはしない。[Cloudflare WAF][S10]

Workersのアカウントプラン別要求本文上限は現行公式でもFree/Pro 100MBである。動画100MBちょうどとフォームの付加分、上限バイト数の実機確認は今回実施していない。[Workers制限][S12] 検査APIの上限を満たしても、この入口の制約が解消するわけではない。

## 5. 非同期・検査用隔離保存を選ぶ場合の影響（AC-3）

以下は検討事項であり、仕様決定でも実装指示でもない。

| 対象 | 決定/整理が必要になること |
| --- | --- |
| V-20・1-6 AC-3 | サイズ超過をR2や隔離先へ保存してから拒否しない。受信バイト数が未確定のままR2へ書く方式で保存前検証を満たしたとはしない。スキャナーの一時保持を含めた「保存」の範囲も明示する |
| 感染検査のタイミング | 保存前・正式保存前・配信前のどれを必須にするか決める。ADR-0011/T-02の保存前説明との関係を整理する |
| 1-6 AC-1・AC-3、EP-1-09 | 「アップロード完了」と「検査済みで添付可能」を分けるか。検査中の表示、投稿を待つか、後から結果を示すか、取消・再試行の意味を決める |
| 1-6 AC-2・AC-7 | 隔離中は本人を含めダウンロード・画像プレビュー・動画Range・サムネイル等の経路から配信しない案。検査後も通常の認可を毎回行う |
| メッセージ/検索/案件公開 | 未検査ファイルを投稿・返信・公開アーカイブ・検索・自分専用の整理スペースから利用できるかを明示する。存在やファイル名の公開範囲も定める |
| 1-6 AC-4・C-74 | 通常の添付は自動期限削除しないという要件と、未完了/感染/失敗の隔離物の保持期限を区別する。隔離物の自動削除は新たな決定であり、黙って追加しない |
| 1-6 AC-6、外部取得URL | SaaSへR2を読ませるための公開バケット・汎用署名URLを既定案にしない。採用するなら検査事業者専用の認証付きWorkers窓口を検討し、署名URL禁止との関係を決める。URLや認証情報をログへ残さない |
| 検査の識別 | 対象キーだけでなく、検査した内容のハッシュ/版とジョブIDを結び付ける。差し替え、重複結果、遅れて届いた結果、削除済み対象を再公開しない案を決める |
| 障害・再試行 | 停止中、429、結果不明、暗号化、サイズ/展開制限、callback偽造・未達、ジョブ消失を区別する。正常結果が得られるまでは配信しない案と、再試行上限・通知・手動復旧の担当を決める |
| 監査・個人情報 | 本文・元のファイル名・取得URL・APIキーを監査ログに入れず、識別子・件数・結果分類・バージョンを必要最小限記録する。外部の保持期間は契約条件と合わせて利用者が承認する |

R2は変更イベントをQueuesへ送り、WorkerまたはHTTPで受け取れる。これは検査ジョブの開始方法の候補であり、イベント通知自体がAVではない。[R2通知][S14] Queuesは少なくとも1回の配信で重複し得るため、ジョブの重複処理を防ぐ必要がある。[Queues配信保証][S15] 検査待ちを `waitUntil` のみで済ませる案も、長いジョブの確実な完了・再試行の保証とはしない。

同期方式でも、SaaS側の一時保存やURL取得元の隔離保存を使う場合がある。**同期/非同期と、保存前/保存後は独立した軸**である。

## 6. Cloudflare内の別候補：Containers上の自前ClamAV

Cloudflareの選択肢をWAFだけと断定しないため、Containersも確認した。`standard-1` は4GiB、`standard-2` は6GiBのメモリを提供し、通常Workersの128MBとは異なる。ClamAVを動かす資源の候補にはなるが、ClamAVの公式対応確認・検証結果ではなく、定義更新や監視は自前のままである。[Containers制限][S18]

Workers Paid $5/月に含まれる枠を超えると、メモリ$0.0000025/GiB秒、CPU$0.000020/vCPU秒、ディスク$0.00000007/GB秒。メモリ・ディスクは割り当て量、CPUは実使用に基づく。Worker・Durable Object・転送等も費用対象なので、実稼働時間がない状態で月額総額を確定しない。[Containers料金][S19]

これは「Cloudflareが定義更新まで請け負うAVサービス」ではなく、**自前ClamAVの置き場所の別案**である。起動時の定義読み込み、再起動後の更新、処理国の制御、ディスクの保持・削除、Workers経由100MBの動作は未確認。現段階で新しい基盤やライブラリの採用を決めない。

## 7. 利用者が決める点と、残る未確認（AC-4）

| 利用者が決める点 | 判断の材料 |

| 検査事業者へのファイル提供を認めるか | 個人情報・社内文書の範囲、外部委託条件、処理地域、保持期間、再委託先の条件。SaaSではハッシュ照会による地域外送信も含めて承認が必要 |
| 感染検査のタイミング・隔離保存の可否 | サイズ超過の保存前拒否は維持。検査用の一時保存とR2隔離を認めるか、利用者に見せる状態、待てる時間を決める |
| 運用を自前で持つか | VM/Containersの定義更新・パッチ・監視・障害対応の担当と予算。冗長化や受付停止の許容範囲 |
| 検査不能・暗号化・失敗時の扱い | 配信を止める案、再試行、隔離保持、削除、本人への案内。各数値・期限は未決定 |
| 最終の方式 | 上記を踏まえて利用者が決め、決定後にADRと実装Issueを作る。今回の推奨を採用とみなさない |

未確認事項は次のとおり。

1. 月間件数・平均ファイル容量・ピーク同時数・許容待ち時間・予算。ClamAVホストの価格・地域、WAFの見積もり・保持条件。
2. 選ぶClamAVの固定バージョンと設定、全許可形式・境界サイズ・展開制限での結果、HTTPS中継の性能、更新時のメモリ、障害時の残存データ。
3. attachmentAVのMB/GBのバイト定義、10MB境界、100MBを60秒で処理できるか、R2の直接S3入力への正式対応、契約/SLA/削除保証の詳細。API定義のform例には公称上限を上回るサイズの応答例もあるため、例の数値で上限を緩めない。
4. WAFの検査地域、ハッシュ等の外部照会、検体/ログ保持・再委託・障害時の契約上の保証。今回読んだ公開資料で確認できないことは「ない」と断定しない。
5. R2のLocation Hintはヒントであり、検査場所の保証ではない。地域を保証するJurisdictionとは別で、既存バケット設定は今回読んでいない。[R2地域][S16]
6. Workersに動画100,000,000バイトを送れるか、実際の転送形式・付加分・メモリ・保存前のサイズ確定方法。AV調査で元の未決定事項を解消したことにしない。

参考としてVirusTotal Private Scanningも公式概要を確認したが、有料の特別権限が必要で、通常の複数AVの判定結果を含まないとされるため、今回の代表的なAVサービス比較候補には採らなかった。Privateでない通常投稿に機密ファイルを送る案は提示しない。[VirusTotal公式][S20]
