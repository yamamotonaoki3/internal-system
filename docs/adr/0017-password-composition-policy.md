# 0017：パスワードの構成規則

- 状態：採用
- 日付：2026-11-06
- 関係：Issue #123、`docs/requirements/00-foundation.md` 0-3 AC-3

## 背景

パスワード変更・初期パスワードの条件を具体化する必要がある。既存要件の8文字以上と大文字・数字・記号の必須条件を、上限や空白・Unicode文字の扱いまで含めて明確にする。

## 選択肢

1. 既存の要件に沿った構成規則を定める
   - 良い点：今回承認された要件の範囲で、利用者に示す条件と受け入れ判定を具体化できる
   - 悪い点：現在のNIST SP 800-63B-4が示すパスワード要件とは異なる
2. 構成規則を課さず、NISTのパスワード要件へ移行する
   - 良い点：文字種の組み合わせを要求しない方針にできる
   - 悪い点：今回の承認済み要件を変更することになり、別途仕様判断が必要

## 決定

今回承認済みの要件として、パスワードは8〜128文字とする。大文字・数字・ASCII記号をそれぞれ1文字以上必須とし、小文字は必須にしない。空白と全角文字を許可し、制御文字は禁止する。禁止パスワードの照合に限り、入力をNFKC正規化して小文字化した値を比較に使う。社員ID・表示名は4文字以上の場合に部分一致で判定し、固定の禁止語一覧は30〜50件を完全一致で判定する。拒否時は理由を区別せず一般的な案内を表示する。この禁止判定用の変換は、実際のパスワードをハッシュ化する前に正規化する方針を定めるものではない。

## 理由

本Issueでは既存要件を具体化する承認済み判断を実装可能な条件に明示する。構成規則と禁止語判定の併用は今回の承認済み範囲であり、規則自体をNIST方針へ変更する仕様変更は行わない。

2025年7月発行のNIST SP 800-63B-4は、単一要素認証のパスワードに最低15文字を要求し、多要素認証では最低8文字を許容している。また、最大長を少なくとも64文字とすること、印字可能なASCII文字・空白とUnicode文字を受け入れることを推奨し、文字種混在などの追加構成規則を課さないよう求めている。今回の8文字下限と文字種要件はこれらと異なる。このIssueの合意は既存要件の具体化に限られ、NIST方針への変更は要件変更として利用者の判断を要する。

## 影響

- 仕様変更により本ポリシーをNIST SP 800-63B-4に沿う方向へ見直す場合、認証方式（単一要素か多要素か）、既存アカウントの移行、利用者への案内を含む要件を改めて確認する
- NIST公式の現行資料は[NIST SP 800-63B-4 §3.1.1.2](https://pages.nist.gov/800-63-4/sp800-63b.html)を参照する。推奨の要点はこのADRに記載した範囲に限る
