# 0011：添付の検査は形式の自前の確認で行い、ウイルススキャンは別Issueで調べてから決める

- 状態：採用（ウイルススキャンと動画の上限は未決定）
- 日付：2026-11-02（利用者の承認は2026-11-02〜03）
- 関係：Issue #105、決定記録 T-02・C-126・C-137・C-153、`docs/requirements/01-messaging.md`の1-1、調査メモ[T-02 再確認：R2・Workersの制限値と料金](../research/T-02-recheck.md)・[T-02 添付とR2](../research/T-02-attachments-r2.md)

## 背景

添付の許可形式と上限は、C-126で決めている（画像10MB・文書25MB・動画100MB・アバター2MB。アップロードと配信はすべてWorkers経由、形式は中身で判定）。C-137は、docx・xlsx・pptxだけを、拡張子と中身（zipの構造）が一致する場合に許可する例外とし、検査の具体的な方式を未決定にしていた。

新しいライブラリは、利用者の承認なしに追加できない。保存前に拒否する要件（V-20）がある。

## 選択肢

### Office新形式の中身の検査

1. zipの構造を自前で読む（ファイル末尾のセントラルディレクトリから、エントリの名前の一覧を得る）。`[Content_Types].xml`と、拡張子に対応するフォルダ（`word/`・`xl/`・`ppt/`）が揃うかを見る
2. zipの小さなライブラリを使う：新しいライブラリの追加になり、承認が要る
3. 1に加えて`[Content_Types].xml`だけを展開し（サイズの上限を付ける）、パーツの種類が拡張子と一致するかを確かめる
4. 保存後に非同期で検査する：保存前の拒否（V-20）に合わず、要件の変更を伴う

### ウイルススキャン

自作は現実的でない。選択肢は、自前サーバーのClamAV、外部の検査サービス、Cloudflareの機能。個人情報・費用・運用が論点で、まだ調べていない。

## 決定

- **Office新形式（docx・xlsx・pptx）は、zipの構造と必須ファイル（`[Content_Types].xml`など）を自前で確認する**。ライブラリは追加しない（選択肢3の方向。zipの読み取りは自前で足りるかを先に試し、重い場合や境界の事例が多い場合に、ライブラリの追加を承認の対象として出す）
- **マクロつき形式（docm・xlsm・pptm等）と旧形式（doc・xls・ppt）は不可**とする（C-137の細部の決定。決定記録C-153に記録する）
- エントリ数・展開後の合計サイズの上限、暗号化されたzip・複数ディスク・ZIP64の扱い、内部の`vbaProject.bin`・`embeddings/`の拒否の要否は、実装の計画で決める（**未決定**）
- **ウイルススキャンは、別のIssueで調査してから決める**。それまでは、**形式の検査と、ダウンロード時の安全なヘッダー**（具体的な項目は実装の計画で決める。Skill「セキュリティ」に従う）で補う。今回の検査は「種類の一致」の確認であり、安全性の保証ではない
- **動画100MBの上限**は、Workersの受信上限（100MB）に余裕がほぼないため、実機で確認して決める（必要なら99MB。**未決定**）。マルチパートのフォームでは、境界文字列と項目のヘッダーが本文に加わる
- R2とWorkersの制限値・料金は、再確認の結果（T-02-recheck.md）のとおり、前回から変わっていない

## 理由

- 自前の確認は、保存前の拒否に合い、新しいライブラリが不要で、「拡張子と中身が一致」の意味が最も強くなる
- マクロつきと旧形式を許可しないのは、利用者の決定である。ウイルススキャンの方式が決まる前に、許可の範囲を広げない
- ウイルススキャンは、個人情報（社内の文書を外部に送るか）・費用・運用の判断が要るため、先に調べる

## 影響

- ウイルススキャンの調査は別Issueで行う。結果によって、非同期の検査（保存後の隔離）が必要になり、要件（V-20）の見直しが出うる
- R2に`put`するとき、ストリームの長さが分かっている必要があるか（`FixedLengthStream`、分割アップロード、いったんメモリに溜める）は、実装時に確かめる（**未確認**）
- 動画の受信のバイト数の数え方（`Content-Length`が信用できない場合に、受信したバイト数で打ち切る）を実装で確かめる
- 見直す条件：ウイルススキャンの方式の決定、Workersの受信上限の変更
