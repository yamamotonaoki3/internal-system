# 0018：予約取引先の初期登録専用migrationを例外的に手作成する

- 状態：採用
- 日付：2026-11-08
- 関係：Issue #192、5-7 AC-9、[project-rules.md](../project-rules.md)

## 背景

予約コード `INT` の取引先は、取引先マスタの初期データとして最初から存在する必要がある（5-7 AC-9）。既存のスキーマ変更ではmigration生成ツールを使う。初期登録データは、開発用seedだけに依存すると、本番を含む新規DBで常に存在するという要件を満たせない。

## 選択肢

1. DDLの生成migrationに初期データ挿入を混在させる
   - 良い点：ファイル数を増やさずに済む
   - 悪い点：生成されたスキーマ変更と業務上必須の初期データの責務が混ざる
2. `INT` 初期登録だけを行う専用migrationを1本手作成する
   - 良い点：必須初期データの投入経路が明確で、通常のDDL生成手順を維持できる
   - 悪い点：生成migrationと異なる作成手順の例外を管理する必要がある

## 決定

`INT` 取引先の初期登録だけを行う専用migrationを1本手作成する。既存migrationは変更しない。テーブル・索引等の通常のDDL変更、およびこの例外以外のmigrationは、引き続き既存の生成手順を使う。この決定はmigrationの作成方法に限り、本番環境への適用を許可するものではない。本番適用は別途利用者の承認を得る。

## 理由

`INT` が初期状態から存在するという承認済み要件を満たしながら、通常のスキーマ変更の生成・レビュー手順を保てるため。

## 影響

- 手作成を認めるのは `INT` 初期登録専用migrationの1本だけとする。テーブル構造・索引・その他の初期データ変更へ例外を広げない。
- 専用migrationは既存の適用済みmigrationを書き換えず、通常どおり新規追加する。
- 本番環境へのmigration適用は、本ADRの承認に含まれず、実行前に別途承認を得る。
