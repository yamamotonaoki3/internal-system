# 0027：絵文字のピッカーを自前の小さな部品にし、emoji-picker-react を入れない

- 状態：採用
- 日付：2026-11-16
- 関係：Issue #138、決定記録 C-128・C-174、[要件 1-7](../requirements/01-messaging.md)（AC-1〜AC-6）、[ADR-0015](0015-style-foundation.md)、[ADR-0026](0026-markdown-rendering.md)、[Q-24-emoji-verification](../research/Q-24-emoji-verification.md)、Skill「frontend-build」・「security」、[tech-stack.md](../tech-stack.md)

## 背景

Issue #138（リアクション・スタンプ）で、投稿に絵文字とスタンプを付けるための選択画面（ピッカー）が要る。

C-128（2026-10-29）は、絵文字の選択画面に emoji-picker-react 5.1.4 を、条件つきで本採用すると決めた。条件は、動的読み込みで初回のサイズを押さえること、ひらがな検索・Space・Tab の問題を確認して直すこと、解決できない場合は自前の最小実装に切り替える余地を残すこと、CSP の方針は別のIssueで決めること、だった。スタンプは画像だけとし、素材は未決定だった。

実装の前に、次の事実が確かめられていた。

- 使い捨ての検証（[Q-24-emoji-verification](../research/Q-24-emoji-verification.md)）で、**`style-src 'self'`（nonce なし・`unsafe-inline` なし）では、ピッカーのスタイルがすべてブロックされて使えない**ことが分かっている。動かすには `style-src` に nonce を足し、`EmojiPicker` に同じ nonce を渡す必要がある
- 本番のCSPは `style-src 'self'`（`public/_headers`）で、ADR-0015 は「実行時にスタイルを注入する方法は使わない」「CSPを理由なく緩めない」と決めている（ゼロトラストの原則。ADR-0012）。nonce は HTML を返すたびに変わる値にする必要があるが、静的アセット配信で HTML に差し込む方法は確かめられていない
- ライブラリの追加（gzip 約143 kB の増加）は、初回のJSの目標（200KB）が#138より前から超過している状況（#160）を悪くする。動的読み込みで初回を避けられるが、その分の設定と確認が増える
- 利用者は、要件として絵文字の検索を求めていない。使いたい絵文字は、固定の一覧（約80個）で足りる

## 選択肢

1. emoji-picker-react を入れ、CSP を変える（`style-src` に nonce を足す）
   - 良い点：絵文字の数が多く、検索もある
   - 悪い点：CSP を緩める。nonce を静的配信で差し込む方法が未確認。ADR-0015 の決定と衝突する。ひらがな検索・Space・Tab の問題を直す作業が残る。サイズが増える
2. emoji-picker-react を入れ、CSP は変えずに、スタイルを外部ファイルで当てる
   - 良い点：CSP を変えない
   - 悪い点：ライブラリが実行時に足すスタイルを外部ファイルに置き換えるのは、ライブラリの内部に依存する。保守が難しい
3. 別のライブラリを探す
   - 良い点：CSP に合うものがあるかもしれない
   - 悪い点：新しいライブラリの調査・安全性の検査・承認がやり直しになる。固定の一覧で足りる要件に対して大きすぎる
4. 自前の小さなピッカーを作る（固定の一覧＋分類のタブ＋キーボード操作）
   - 良い点：新しいライブラリがなく、CSP・ADR-0015 を変えない。既存の `Button`・固定のユーティリティだけで作れる。一覧を `shared/` の1か所に置けば、サーバーの検査と画面で同じ定義を使える。サイズの増加は数 KB
   - 悪い点：絵文字の数が限られ（約80個）、検索がない。キーボード操作・読み上げの属性を自分で作り、テストで確かめる必要がある

## 決定

選択肢4を採る。利用者が決めた（Issue #138 の U-1）。

- 絵文字のピッカーは自前で作る。emoji-picker-react は入れず、`package.json` は変えない。CSP（`public/_headers`）と ADR-0015 は変えない
- 受け付ける絵文字は、`shared/reaction-rules.ts` の固定の一覧（4分類・80個）にあるものだけ。サーバーも同じ一覧で検査する。肌の色の選択は出さず、異体字セレクタなどの正規化はしない（完全一致）
- スタンプは、画像ではなく文字の6つ（いいね・了解・ありがとう・お疲れさまです・確認します・おめでとう）。C-128 の(3)「スタンプは画像だけ」を置き換える（素材の未決定は不要になる）
- 絵文字は端末のフォントで描く（native 表示）。外部CDNは使わない（C-128のこの部分は変えない）
- 検索欄は作らない（約80個のため。ひらがな検索の問題も避けられる）
- 動的な読み込みは行わない（部品が小さいため）
- キーボード操作はWAI-ARIAのパターンに合わせる：分類のタブ（ローヴィングtabindex、←→・Home・End）、絵文字のグリッド（Tabで止まるのは1セル、矢印・Home・End・Ctrl+Home・Ctrl+End、Enter・Spaceで選ぶ）、Escで閉じてフォーカスを開いたボタンに戻す。C-128の検証で問題になった「Tabが全セルで止まる」「Spaceで選べない」を起こさない
- C-128 の(2)（emoji-picker-react の本採用）を置き換える。置き換えの記録は決定記録 C-174

## 理由

- 本番のCSPのもとで動く唯一の方法を、新しい依存もCSPの緩和もなしに満たせる。CSPを緩めない原則（ADR-0012・ADR-0015）を、機能の都合で崩さない
- 固定の一覧にすることで、サーバーが許可リストで値を検査でき（Skill「security」）、画面とサーバーで同じ定義を使える。ライブラリの絵文字のデータは、サーバー側では使えない
- 業務の連絡のリアクションには、固定の約80個で足り、検索は要件にない。機能を1つ減らす方が、CSPを緩めるより安全
- 初回のJSの超過（#160）を悪くしない。実測では、#138で最初に読み込むJSが gzip 約9.9KB（273,411B → 283,321B）増えた。ライブラリを入れる場合の約143 kBに比べて小さい

## 影響

- 絵文字は80個に限られる。増やすときは `shared/reaction-rules.ts` の一覧に足し、サーバーと画面の両方に反映される。変更の理由が同じ定義を1か所に置いているため、食い違いは起きない。一覧を増やす要望が出たら、この決定を見直す（検索が要る規模になったら、ライブラリの再検討をCSPと合わせて行う）
- キーボード操作・読み上げの属性は自前のため、単体テストとE2E（`e2e/reactions.spec.ts`）で確かめる。実機のスクリーンリーダー・スマートフォンでの確認は、別途の確認の対象として残る
- 絵文字の描画は端末のフォント任せ。新しい絵文字（Emoji 14以降など）は、古い端末で描画できないおそれがある。一覧に新しいものを足すときは、対象のブラウザ（`nonfunctional.md`）で描画できるかを確かめる
- スタンプは文字のため、素材の出どころ・ライセンスの問題はない。`img-src` の方針も変えない
- `docs/tech-stack.md` に、入れないライブラリとその理由を記録する。[Q-24-emoji-verification](../research/Q-24-emoji-verification.md) に、自前にした注記を足す
- 設計は [設計書 reactions.md](../design/reactions.md)

## 実測の結果（2026-11-16）

- 最初に読み込むJS（`npm run build`後の計測）：gzip 283,321 B。ADR-0026の記録（273,411 B）から約 +9.9 KB。目標の200KBは#138より前から超過しており、追跡は#160
- 動的読み込みを使わない判断は、この増加の大きさで妥当と見た。超過の解消は#160で扱う
