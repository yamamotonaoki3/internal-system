# 0021：初代部署の専用チャンネルを補うmigrationを例外的に手作成する

- 状態：採用
- 日付：2026-11-09
- 関係：Issue #196、[ADR-0018](0018-client-initial-seed-migration-exception.md)、7-1 AC-1・AC-2、[project-rules.md](../project-rules.md)

## 背景

部署を作ると、公開の専用チャンネル2つ（通常・お知らせ）が自動でできる（7-1 AC-1）。Issue #196でこの仕組みと、チャンネルの表（`rooms`・`channels`・`channel_members`）を初めて作る。#196より前に作られた部署（初回セットアップの初代部署など）には専用チャンネルがない。専用チャンネルを持たない部署が残ると、#200・#201が前提とする「どの部署にも専用チャンネルがある」が成り立たない。

通常のDDLの変更は、migrationの生成ツールを使う（ADR-0018）。既存の行にデータを補う処理は、生成ツールでは作れない。

## 選択肢

1. 既存の部署に補う専用の手作成migration（0009）を1本置く
   - 良い点：新規DBでも既存DBでも同じ手順で、部署のある状態が補われる。適用の記録がmigrationの履歴に残る
   - 悪い点：生成手順と異なる作成手順の例外が増える。名前が衝突する部署は補えない
2. 今後のセットアップでの作成だけを変更する（`setup.repository.ts`）
   - 良い点：migrationの例外が増えない
   - 悪い点：すでにある部署は補われない
3. 補わず、補えていない事実を記録するだけにする
   - 良い点：データ移行のリスクがない
   - 悪い点：既存の初代部署に専用チャンネルがなく、後続Issueが前提を満たせない

## 決定

選択肢1を採る。あわせて、今後のセットアップは`createInitialAdmin`が専用チャンネルを作る形に変える（選択肢2の内容）。

- 手作成を認めるのは「初代部署の専用チャンネル2つの補完」の1本（`0009_backfill_department_channels.sql`）だけ。ほかの手作成は認めない
- 名前が既存のチャンネル（アーカイブ済みを含む）や、補う部署どうしと衝突する部署は補わない。通常・お知らせの両方とも作らず、`audit_logs`に`department.channel_backfill`・`failure`を1件記録する。migration自体は失敗させず、ほかの部署は補う
- 何度流しても同じ結果になる（べき等）。すでに専用チャンネルを持つ部署は対象にしない
- 既存のmigrationは変更しない
- 本番への適用は、この決定に含まれない。本番適用の前に、ローカルで「0007まで適用→部署を作る→0008・0009を適用」のリハーサルを行い、利用者の承認を得る

## 理由

後続のIssueが「部署には必ず専用チャンネルがある」ことを前提にできるため。名前の衝突を黙って別名にすると利用者の意図しない名前が付き、migrationを失敗させると他の部署が補われず適用が止まるため、衝突した部署だけを補わずに記録する。

## 影響

- ADR-0018に続く、手作成migrationの例外の2本目。例外をこれ以上広げない（ほかのデータ移行は、新しいADRで判断する）。
- **名前が衝突して補えなかった部署は、専用チャンネルを持たないまま残る**。この部署を改名しても、改名の最後の確認は「名前が違う自動チャンネルがない」ことだけで、2チャンネルの存在は確かめないため、改名は成功してもチャンネルは揃わない（作成のbatchには存在数の確認がある）。復旧は、運用の手順（衝突を解消してから、専用・お知らせの2チャンネルと参加者を作り直す）、または、改名のときに足りないチャンネルを作る別Issueで行う。どちらも未実施で、`audit_logs`の記録から対象の部署を見つけられる。
- チャンネルのルームIDは、部署IDの2文字目だけを専用は`Y`、お知らせは`Z`に置き換えた26文字で作る。ほかのルームIDと偶然ぶつかると、主キー違反でmigration全体が失敗して適用が止まる（データは壊れない。トランザクションにより取り消される）。また、IDのULIDの時刻の部分は、チャンネルの作成時刻ではなく部署の作成時刻に近い値になり、チャンネルの実際の作成時刻とずれる。
- 通常のDBテストは空のDBにmigrationを流すため、補完のmigrationは別に検証が要る（`department-channel-backfill.db.test.ts`）。既存の部署データがある実DBへの`wrangler d1 migrations apply`での適用は未確認。
- 無効な部署も補う対象に含まれる。
