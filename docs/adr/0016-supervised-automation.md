# 0016：プロジェクト継続作業の監視付き自動実行

- 状態：採用
- 日付：2026-11-06
- 関係：本プロジェクトの既存Issue（記録を作成した作業単位：#123）

## 背景

承認済み要件と既存Issueに沿って本プロジェクトを完成まで進める今回の継続作業では、通常の利用者確認を各工程で挟むと、実装・記録・品質確認・統合が細かく中断される。並列に進められる独立した変更も、逐次実行では時間がかかる。一方で、未承認の仕様や本番反映など、判断が必要な操作まで自動化すると利用者の意図を越える。

## 選択肢

1. AGENTS.mdとSkillの標準手順どおり、利用者確認を各工程で行う
   - 良い点：各段階で利用者が判断できる
   - 悪い点：承認済みの範囲でも作業のたびに中断が発生する
2. 今回の継続作業に限定して、統括の監視下で承認済み要件・既存Issueに沿った作業を包括的に進め、通常動作確認をAIの自動検証・画面確認に置き換える
   - 良い点：受け入れ条件と品質ゲートを維持しながら、不要な中断を減らし、独立した変更を並列に進められる
   - 悪い点：自動検証や画面確認で見つけられない問題が残る可能性がある

## 決定

利用者は2026-11-06の会話で、本プロジェクトを完成まで進める今回の継続作業について、承認済み要件と既存Issueを対象として次の範囲を承認した。Issue #123は、この承認を記録した作業単位であり、適用範囲を同Issueだけに限定するものではない。

- 統括が作業を監視・指示し、承認済み要件の実装、Issueへの作業記録、commit・push・PR作成を行う
- 全品質チェック・テスト・別AIレビューが合格した後、Squash mergeを行う
- コミット前の利用者による通常動作確認は、AIによる自動検証と画面確認に置き換える
- 変更ファイルが競合しない複数エージェントの並列分担は、統括に一任する
- 仕様変更、新規ライブラリの追加、破壊的操作、本番環境への反映は、従来どおり個別に利用者へ確認する

この例外は、承認済み要件・既存Issueに基づいて本プロジェクトを完成まで進める今回の継続作業に限る。未承認の仕様や第2段階への移行等を自動承認とみなさず、追加の要件合意が必要な場合は利用者に確認する。AGENTS.md、Skillなどハーネス管理ファイルのMUST自体は変更しない。

## 理由

利用者が要件を承認した後の実装・検証・統合作業は、統括が進捗を監視し、Issueに記録し、全品質ゲートと別AIレビューを通すことで制御できる。通常動作確認は自動テストと画面確認で証跡を残す。これにより、利用者の確認負担を減らしながら、品質上の確認を省略せずに進められる。

## 影響

- 自動化された検証で不備が見つからないことを、成功の根拠として扱わない。受け入れ条件に対応する自動検証と画面確認の証跡を記録する
- テストや品質チェックの失敗、未確認、実行不能を成功扱いにせず、回避策でCIや品質ゲートを迂回しない
- 並列分担では担当ファイルの所有範囲を分け、競合が生じた場合は統括が調整する
- この承認は破壊的なcleanupや履歴破棄の権限を広げない。該当操作は個別確認を要する
- 仕様変更、新規ライブラリ、破壊的操作、本番反映には、引き続き利用者の個別判断が必要
- 仕様変更が必要になった場合は、変更内容・理由・影響範囲を利用者へ示して実装前に確認する。実装中の問題は、原因・対応・検証結果・残存する制約をIssueへ記録する（2026-11-06の利用者指示）
- 自動検証・画面確認では判断できない利用者の意図、実環境固有の挙動、または個別確認を要する事項は、利用者へ確認する
- 今回の継続作業の範囲を越える新たな作業や段階にこの例外を適用する場合は、改めて利用者の承認を得て、適用範囲を記録する
