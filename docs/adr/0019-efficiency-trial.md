# 0019：次の1Issueで運用改善を試行する

- 状態：採用（1Issueの試行）
- 日付：2026-11-08
- 関係：管理Issue #189、試行対象 #125、[ADR0016](0016-supervised-automation.md)
- 一部置き換え：ミューテーション・E2Eの全体実行に関する部分は、[ADR0020](0020-test-scope-mutation-e2e.md)が置き換える（2026-11-09）

## 背景

利用者は2026-11-08、`reports/harness-efficiency-proposal.md`について「導入し、次のissueを進めて。次で問題あれば修正」と承認した。調査・検証・引継ぎの反復を減らす本プロジェクト限定の試行であり、ハーネス全体の規則改定ではない。

## 選択肢

1. 一律の役割・検証時期を維持する。追加判断は少ないが証拠の再取得が続く。
2. 必須の品質と独立性を維持して1Issueで運用を試す。効果は未確認なので記録して見直す。

## 決定

選択肢2を採用し、次の #125を試行対象とする。未決仕様の回答・要件合意と依存確認後に実装する。AGENTS.md・Skillの役割分離、工程ごとの全体検証、前Issueのマージ後の次Issue着手について、次の範囲だけ例外とする。

- 小は短い計画で作成・文書・品質確認を兼務でき、通常は計画・文書・品質確認等を兼務できる。影響大は現行の役割分離を基本とし、分類理由・担当をIssueに記録する。
- テスト先行、テスト担当と実装担当の分離、実装担当のテスト編集禁止、必要な計画レビュー、別AIの独立レビュー、最大3回と安全上の重大指摘の例外を維持する。
- 開発中は対象検証、変更確定後は最終状態の必須全体ゲートを満たす。重要範囲のミューテーション80%以上、対象・除外・期待結果を緩めず、限定診断やツール障害の別Issue化で通過扱いにしない。証拠の再利用は[試行手順](../operations/efficiency-trial.md)の一致条件を満たす範囲だけとする。
- 同一原因の修正失敗2回または調査開始から30分で追加実験・追加エージェントを止め、証拠・選択肢・追加見積と不確実性を利用者へ示す。原因の言い換えで枠を取り直さない。未達は完了扱いにせず、追加調査は判断後に進める。
- 独立Issueの同時着手は最大2件で義務ではない。所有ファイル・共有状態・統合順を定め、同じ共有環境の品質担当は1名とする。回答待ち中は依存しない承認済み作業だけ進める。

ADR0016の既存包括承認と最後の利用者確認は保持する。仕様・新規ライブラリ・破壊操作・本番・秘密情報の扱いの変更は別承認。既存のマージに伴うリモートブランチ自動削除の許可は継承する。今回の試行を根拠に、手動削除・ローカル削除など新たな削除権限は付与しない。ハーネス管理ファイル変更・同リポジトリへのIssue作成を含めない。後発Issueを元50件へ自動追加せず、#189は最後の全体確認と利用者の完了判断まで閉じない。

## 理由

必須ゲートを保って重複作業を減らす判断を試せるため。消費量・短縮効果は未集計であり削減率は主張しない。

## 影響

承認台帳・6項目引継ぎ・完了件数と進行中件数は試行手順に従う。#125終了時または問題発生時に証拠と改善案を記録し、品質を損なう運用は止めて従来の厳しい手順へ戻す。振返りで継続・修正を判断し、他Issueへ自動拡大しない。
